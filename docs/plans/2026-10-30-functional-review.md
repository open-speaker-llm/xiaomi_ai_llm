# 功能审查与优化执行方案

审查日期：2026-10-30。代码基线：`e2b6fb7`。范围覆盖设备端首问、原生路由、LLM、语音播放、上下文追问、可选服务端、安装恢复和日常维护。

## 结论与产品方向

项目已经形成“保留原生小爱 + 音箱直连 LLM + 语音播放 + 连续追问”的闭环。下一阶段的优先级是：**异常后能恢复、问句和上下文不失真、维护不会破坏已有能力，再改善追问路由与播放等待。**

历史决策需要继续保留：

- 原生唤醒、识别和家控优先复用；boot1 原生追问已形成独立运行路径，不重新把常驻 Mac 作为主线依赖。见[原生追问记录](../history/2026-09-06-boot1-native-followup.md)。
- 用户曾明确要求 LLM 连续播放时仍能唤醒小爱控制家电。因此，播放中再次唤醒默认停止 LLM 会改变已验收行为；停止播报应作为另行设计的明确指令或可选模式。见[并行唤醒实测](../history/2026-09-09-parallel-wake-reference.md)。
- 首轮本地判停解决句中短暂停顿，不能据此声称能理解语义是否完整。追问目前沿用另一条收音路径。见[当前能力](../status.md)。
- 两次历史播放停顿有句级 TTS 失败重试证据，缺少当时的完整阶段记录和声学时间戳；不能直接认定是 LLM 速度或凭经验调整 VAD。见[播放停顿分析](../history/first-turn-endpoint/playback-stall-20260919.md)。

### 接口和失败行为约定

1. native 主线不把传输中断、截断生成、失败播放记作一轮完整 assistant 回答。
2. 服务端 TTS 首包前失败以非成功 HTTP 状态返回；首包后失败以传输失败结束。不能先返回成功 WAV 头再吞掉所有合成异常。
3. 设备只有在未播放有效音频时才允许整段原生兜底；部分已播后失败应结束该轮，避免整篇重复播报。
4. 首问失败退出后，预热录音、忙碌状态、LED 和原生播放/收音资源应恢复；下一次真实唤醒仍可使用。
5. 文件调试接口保留接口形状，但只允许读写其专属目录。它不是通用文件管理器，仍没有成为可公开暴露的认证服务。
6. 旧恢复脚本是旧代码的快照。修复仓库不会自动修复设备上的备份；按[整包维护说明](../../device/native_endpoint/README.md)准备恢复目录后再执行旧脚本。

## 第三阶段：追问更自然

以下是后续产品与实现任务，尚未接入日常客户端。

### 追问中的原生指令

当前 `handle_llm_dialog` 的追问分支直接把识别文本交给 LLM；首次原生路由与追问路由不是同一套逻辑。“把客厅灯打开”在追问中可能只得到聊天回答，不能把回答中的“好的”当作真实执行。

执行方案：产品定义一组明确家控、音量及会话控制意图；开发先在隔离路由器中测试，再接入已验证的原生 NLP 入口。普通开放问答留在原 session，明确家控转原生；歧义输入保留澄清，不能让模型自由生成设备动作。boot0 文件 ASR 与 boot1 ASR-only 分别验证。

验收必须包含：首问正常问答后说家控、否定句“不要开灯”、引述“他说把灯打开”、开放问答、同句多个动作、原生失败，以及真人确认家电动作。能识别文本或得到原生成功码不等于家电动作已验收。

### 结束对话、停止播报与上下文

当前“退下”等结束语仍作为普通 LLM 输入。应先定义追问窗口内明确结束语：结束后不再调用模型、不继续录音；重新唤醒建立新 session。清空上下文与停止当前播报分别定义，避免一个短词同时触发多个副作用。

播放中停止需要独立的取消传播设计：终止本轮生成、合成和播放，释放相关资源，隔离晚到结果并恢复原生状态。默认“再次唤醒并行控制家电”继续保留，不能用停止 LLM 来代替 AEC 或并行唤醒问题的解决。

验收覆盖取消发生在生成、合成、播放和等待追问各阶段；退出后下一轮可用；普通家控唤醒仍保持连续播报。此项需要真实设备与用户听觉验证，不宜仅凭 shell 替身测试启用。

## 现场验收与放行条件

主机回归之后，候选包仍需按 [TESTING.md](../../TESTING.md) 和[人工用例](../../tests/manual_native_first_cases.md)验证：

1. 先记录真实固件、活动分区、组件摘要、配置模式和回滚点，再安装候选包。
2. 分别测试 boot0/boot1 的正常首问、带引号问句、上下文追问、静默退出与原生报时。
3. 测试 LLM 请求失败、TTS 首包前失败、部分播放后中断；核对实际声音、退出待机、下一轮唤醒，不只检查日志。
4. 验证播放中家控仍可用、LLM 不中断；不修改已验收的 AEC 与音量行为。
5. 对安装、回滚和重启做真实验证；旧备份目录准备与新备份分别记录。
6. 最终包再建立全天及多噪声/距离样本，记录运行时长、轮次、失败数、PID/RSS/FD/空间与恢复结果。早期文件回放次数不挪用为最终包现场证据。
