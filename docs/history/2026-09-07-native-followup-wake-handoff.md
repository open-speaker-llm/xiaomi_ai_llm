## 故障证据

2026-09-07 用户反馈：第一轮 LLM 播完、绿灯等待追问时，再喊“小爱同学”无法控制家居，后续话语进入 LLM。

21:24:26 客户端开启 ASR-only 追问，21:24:30 收到“小爱同学”，播放输入补全提示后又开启 ASR-only 追问。组件日志同时记录 `physical wake ignored during owned followup`。真实唤醒回调被主动丢弃，而追问请求设置 `disabled=["NLP","TTS"]`，因此后续家居命令无法进入小米原生语义处理。21:23 的前一轮也有相同记录。

证据快照位于本机 `/private/tmp/xiaomi-native-handoff-20260907/`，该目录为临时诊断产物。

## 修复

- 真实唤醒撤销当前追问所有权，置 `NATIVE_HANDOFF` 并清空文本；先释放 busy 标记，再执行原生唤醒回调。
- 控制程序返回专用状态 125，保留旧 prepare/dialog 用于取消隔离，不输出已有的 final 文本。
- 软件唤醒启动与真实唤醒回调串行，避免延迟的软件 IVW 完成插入新的原生收音。
- 旧追问迟到的 StopCapture、Finish、Abort 等指令被隔离，新的原生 dialog 正常透传。
- 打开追问收听前完成旧播放器队列清理和音量恢复；交接后仅停止 LLM 灯效刷新，不再静音、停止播放器或关闭原生灯效。
- 不喊唤醒词的普通追问继续使用原 LLM session。只有 ASR 文本匹配、没有真实唤醒事件时，保留此前的短句补全兜底。

这次不调整首轮云端 VAD，也不实现 LLM 播放打断。
