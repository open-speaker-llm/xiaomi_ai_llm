# 2026-09-06：boot1 处理后 PCM 连续追问

> 后续已实现并安装 [原生 ASR 连续追问](2026-09-06-boot1-native-followup.md)，无需 Mac 识别程序。本文保留 PCM + Mac 路线的实现和历史验证，供回退参考。

适用设备：S12A / MDZ-25-DA，boot1/system1，ROM 1.76.54。

## 结论与边界

**免唤醒连续追问已经实测打通**，安装后重启也再次成功。链路是小米前端处理音频 → 本机小缓冲区 → Mac Whisper small → 音箱原有 LLM session → 音箱原有 TTS。

这不表示 boot1 的原生文件 ASR 或云端 reopen 已经可用。当前依赖 Mac 在线，每次固定收听 8 秒；未实现说完即停、播放中打断或区分电视与用户的声音。通用配置默认仍关闭，只有匹配固件并安装组件后才启用。

用户要求“退下”“不要再讲了”等结束语无需特殊处理，因此最终版本仍交给 LLM 自然回应。保持安静后，ASR 空结果或低置信度结果结束本轮会话，恢复小爱。

> 同日后续研究已实测打通 [NONWAKEUP 原生识别入口](2026-09-06-boot1-native-asr-research.md)，不依赖 Mac 识别；尚未接入 LLM 追问。本记录描述的正式部署依旧使用 Mac ASR，不能把研究验证写成已经替换部署。

## 为什么这次能工作

旧实验主要在两个位置尝试：抢占 ALSA 原始麦克风，或让小米重新建立云端 ASR 会话。前者会干扰原生音频链路；后者被云端会话状态限制。`speech.usock` 上传流也不是空闲时持续可读的录音源。

这次从 `libxaudio_engine.so` 的 `xaudio_wrapper_dnn` 返回处复制处理后的输出，位置在上传门控之前。实测空闲时也约每 10ms 调用一次，因此无需重新唤醒小爱或抢麦克风。

- 内核是 ARM64，原生 `mipns-xiaomi` 与音频库却是 ARM32，采样共享库必须按 ARM32 glibc 2.25 构建。
- 每次 640 字节输出由两段各 160 个 S16 样本组成，使用第一段拼成 16 kHz 单声道；不能当成交错双声道或 32 kHz 单声道。
- 原函数照常调用，返回值和输出不变；采样只复制一份。约 83KB 环形缓冲区保存最近 2.56 秒，录音从调用之后的新帧开始。
- 格式、生产者、覆盖/半帧、停滞和原生静音状态均检查；无效录音不交 ASR。

固件哈希、构建命令、安装与回退见 [组件说明](../../device/pcm_tap/README.md)。

## 退出时轻微残留声音

根据 `mediaplayer` 从暂停恢复、再处理 `ubus stop/reset` 的时序，怀疑队列中的原生失败提示在 stop 生效前漏出了开头；尚不能仅凭日志确定用户听到的具体字音。

最终补充：boot1 的 LLM 会话清理时，先保存/检查原有 `Hard Mute` 状态，在恢复播放器和清空队列期间临时关闭声音，恢复原生音量后再解除本次静音。原先已经静音则不擅自解除；退出清理也优先恢复本次静音。boot0 与非 LLM 原生流程不走此分支。

2026-09-06 11:28 已部署该修正。11:34 日志确认先静音清队列、恢复音量、再解除静音，回到 IDLE；随后用户对“残留声音消失、时间播报正常”的对照回答“正常了”。这是本轮听觉验证结果，不保证所有固件和时序都无漏音。

补充发现：11:30 一轮安静/背景音采样曾产生多句无意义追问，Whisper logprob 在 -0.80 至 -0.95，旧门槛 -1.0 没有全部滤掉。独立 PCM 追问服务因此将门槛收紧为 -0.75，已把现场分数加入回归用例；正确追问的 -0.36/-0.53/-0.55 仍通过。旧通用 ASR/boot0 调用保持原门槛。更严格过滤可能舍弃低声或模糊的有效追问，仍不能识别声音是否来自电视。

## 持久安装与恢复

音箱组件在 `/data`，由客户端开机调用 `native_pcm_tap.sh start`。每次校验原生二进制与 PNS 脚本的 SHA-256，使用内存中的 PNS bind mount 注入，不刷固件。健康检查失败则撤销挂载、恢复原生服务，并禁用本次追问，保留首轮 LLM。boot0 不加载此组件。

本次原版本备份：`/data/native-pcm-backup-20260906-111804/`，包含 `restore.sh`。恢复到本次改动前：

```sh
sh /data/native-pcm-backup-20260906-111804/restore.sh
```

最终客户端 SHA-256：`2d2709815ed6990be63272d4beb25a193aa2564bde1c41d72b807fd1a5848760`。

Mac 服务独立安装在 `~/Library/Application Support/xiaomi-ai-llm/followup-asr`，模型和运行代码均脱离临时 worktree。`org.open-speaker-llm.followup-asr` LaunchAgent 配置登录自启与异常重启，已通过 launchd 重启和健康检查。Python 依赖环境仍使用安装时指定的固定路径；没有重启 Mac 验证登录流程。
