# 轻声续说、纸张声与 SDK 结束竞态

沿用 seq 41 正常录音作基线；本轮在同一次临时 setup 中运行 seq 42/43。实验库为 `7f32a809…`，模式 5 显式 capture，原样转发麦克风并保存最多 20 秒同源 PCM。每轮绑定后才提示说话。结束后恢复原服务。

## 两个现场结果

| 项目 | 轻声续说 seq 42 | 纸张声 seq 43 |
| --- | --- | --- |
| 目录 | `trial.capture.5.2Rv646` | `trial.capture.5.SyuExb` |
| dialog | `ca0c944172963e33e30281ef927db04a` | `477df3f62c3866d387583b30b8abf7ca` |
| 起始 CST | 10:52:38 | 10:54:56 |
| 最终文本 | 苹果的种子为什么会发芽请用一句话回答 | 苹果的种子为什么会发芽 |
| 结束原因 | hard-limit | hard-limit |
| 累计音频 / 最后确认 VAD 语音 | 20000 / 19950 ms | 20000 / 19610 ms |
| 最后可用 ASR end offset | 14040 ms | 7880 ms |
| 最后不同 partial 到 EOF | 5776 ms | 11876 ms |
| 保存 PCM | 640000 字节 | 640000 字节 |

用户确认 seq 42 按要求停顿约 1.5 秒、轻声补充、只说一次且没有报错。后半句保留，但到硬上限才结束，不能算正常判停通过。seq 43 用户确认按要求说完轻揉纸约 1 秒，**同时报告听到“网络遇到问题，请稍后再试”**。不把 CLI 0 或 final/Finish 标志当作 SDK 整轮成功。

两份 PCM 在音箱独立进程使用原 VAD/状态机重算，均复现 hard-limit 和相同 last_voice 位置。正常基线 seq 41 则为 quiet 8870 ms。异常输入现在可离线复核，不再只靠边沿日志猜声音来源。

## 网络提示发生在完成边界

seq 43 系统日志：10:55:17.026 左右原生采集正常停止，17.046 发送 RecognizeStreamFinished，17.136746 SDK 检查到同一 dialog 的 TTS timeout，17.139233 把已经排队的 Dialog.Finish 忽略，随后 onError=50010005。探针先前已经在 JSON 解析时记录 final/Finish 并允许 CLI 返回。

因此两个“完成”不是同一时刻：探针解析完成，早于 SDK 从队列处理 Finish。此前 timeout guard 在 COMPLETE/IDLE 立即撤销，SDK 会重新读到原本的 10 秒，而最后 partial 已过去约 12 秒，于是就在消费 Finish 前超时。这个边界与日志顺序相符，并由后述针对性回放验证修改。

提示在 EOF 之后发生；PCM 已停止并保存，因此该次提示不能解释此前整段 VAD 持续阳性。纸张轮保留“完成时有 SDK 报错”的异常标记，但不能反过来说录音尾部必然包含这句提示。

## 最小实验修正

只修改主动实验的 `sdk_timeout_scope`：对于同一 sequence/owner/dialog，正常 final_seen+finished 的 COMPLETE/IDLE 也保留保护，直到原有 armed/owner/截止时间不再有效。没有延长 25 秒租约，也不改变原生控制结构、麦克风/ASR 内容或错误提示。真实唤醒 NATIVE_HANDOFF、FAILED、换轮、缺少 final/Finish、过期或 owner 消失均不延续保护。SDK getter 无 dialog 参数的隔离限制仍在，不能直接用于任意并发生产对话。

单位测试新增：正常排空期间保护、未完整完成的 IDLE 不保护、过期/换轮/交接撤销。实验库 SHA256 为 `7797e467a65820eb40876be5274301e6642f5ff7a9175b37733e5f3e3822b07e`，132 项回归和 shell 语法检查通过，设备独立测试通过。

新增 `trial tail 3`：7.3 秒旧问题 PCM 后接 11 秒静音，总 18.3 秒，使最后 ASR 进展到 EOF 超过原超时值。seq 44 `trial.tail.3.CGdf23`、seq 45 `trial.tail.3.djoYDW` 连续两次 CLI 0、final/Finish 正常，系统日志均明确 `client process Dialog.Finish done`，没有 TTS timeout。这次只回放旧录音，没有采集新的用户内容或调用 LLM。证据 `drain-device-test.txt`、`drain-checks.txt` 和忽略目录的两份 trial。

## VAD-only 低频过滤对照：未采用

对正常、轻声、纸张三份录音做离线算术分析，不做 Mac ASR。正常静默与轻声轮部分尾部的频谱能量集中在 250 Hz 以下，但声音来源没有人工标注，不据此认定风扇、风声、呼吸或人声。

`filter_vad_pcm.c` 仅在音箱独立进程处理已保存 PCM，对送入 VAD 的副本试验 80/120/180/250 Hz 一阶或两级高通；不调用 SDK，不生成修改后的云端音频。原始判停与“收到首个非空 ASR 后才允许 quiet”的离线候选分别统计。后者使用录制的到达时间近似映射到音频轴，是观察性推演，不是已经接入的实时方案。

| 样本 | 未过滤 | 候选过滤结果 |
| --- | --- | --- |
| 正常 seq 41 | quiet 8870 ms | 约 8820–8880 ms，无实质改善 |
| 轻声 seq 42 | 20000 ms 硬上限 | 加 ASR 开始约束后仍约 19510–19650 ms；直接替换有的在 3610/4700/8470 ms 就结束，早于用户本轮开口 |
| 纸张 seq 43 | 20000 ms 硬上限 | 250 Hz 约 17210–17220 ms，其余大多仍到上限；某参数直接替换在 2640 ms 提前结束 |

因此没有采用高通参数，也没有把“ASR 开始约束＋过滤”宣称为完成修复。仅缩短一点硬上限等待不够，早于用户开口结束更不能接受。轻声样本仍有较长拖延，说明这些简单参数没有提供所需区分能力。

20 秒样本单次离线 CPU 时间：原始约 35 ms，一阶过滤加 VAD 约 38 ms，两级约 43 ms（约单核 0.17%/0.19%/0.22% 实时比例）。这只是独立程序的计算开销，不包含真实服务、锁、网络与日志；不能作为整机负载结论。结果 `filter-41.txt`、`filter-42.txt`、`filter-43.txt`。

已提取轻声轮 14.5–20 秒原幅度音频，供用户辨认尾部声源；没有增强音量或自动转写。用户听后确认：“是室外的声音，没有人说话的声音”。据此将 **seq 42 的这个时间范围**标为室外非人声，不扩展到整段录音或 seq 43，也不推断具体是风、车辆或其他声源。原 VAD 在这一段仍反复累计到确认语音，足以证明本次拖到硬上限存在非人声误检。

后续保存样本的自适应背景门槛、合成轻声压力测试，以及神经网络 VAD 的设备兼容性检查见 [噪声判停可行性记录](noise-feasibility-20260919.md)。没有新增现场录音，没有采用或部署候选门槛。
