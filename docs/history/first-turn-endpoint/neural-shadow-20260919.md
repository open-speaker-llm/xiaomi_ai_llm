# 神经网络 VAD 实时旁路验证

本轮已完成从文件推演到音箱真实 ASR 音频回调的旁路观察。**不把候选接到结束函数**：只记录候选，固定窗口结束后才由已有实验控制器正常结束 ASR。生产首轮、LLM 路由和历史没有部署新规则。

## 实现与隔离

新增主动实验模式 6，仅通过 `run_active.sh trial neural 6` 显式进入。它沿用独占 ASR-only 的 sequence/owner/dialog、唤醒撤销和超时保护，原样传递麦克风 PCM。

- `neural_shadow.c` 先加载模型，再创建本轮专属的线性共享缓冲区并打印 READY；模型初始化约 1.9 秒在 listen 之前完成。
- 缓冲区文件名同时包含 sequence 和 owner；0600、O_EXCL/O_NOFOLLOW、大小/身份校验。每帧只写一次，发布 used 计数后才允许观察进程读取，绝不循环覆盖。旁路映射初始化后降为只读。
- 原生回调只复制 PCM 和原子发布，不等待模型、不做推理；观察进程每次处理 10 ms 输入。原始 ASR 回调内容保持不变。
- 新进程/新模型实例对应每轮。真实唤醒立即标记无效；控制器每 20 ms 核对租约，换轮、final、失去 armed、静音或观察进程退出均撤销。观察进程也校验 owner/producer 存活、身份、发布计数；断流或积压超过 250 ms 时输出 invalid。此前日志里的候选只在最终 status=ok 时可作为观察证据。
- 先有模型 READY，再有精确 BOUND 和首批 PCM 的 NEURAL_STREAM，才向用户发开始提示。观察程序没有 SDK、控制器或网络调用，没有结束对话的权限。

最初窗口为 20 秒，第一轮句后余量不足。随后**只对模式 6**调整为 24 秒、768000 字节上限和 30 秒租约/本地等待；观察进程寿命最多 28 秒。原有模式 4/5 的判停参数及 25 秒租约保持原值，SDK 专属保护仍为原来的 30 秒。无界延长、把无声等待当已完成都不采用。

运行库仍以独立加载器隔离于原生进程；来源、模型和 ABI 见 [文件实测记录](neural-vad-20260919.md)。`run_neural_shadow.sh` 以主机给出的 manifest SHA256 校验所有运行组件，限制地址空间 96 MiB、CPU 20 秒并禁用 core dump。该 helper 仅在试验中存在，不是外部服务或常驻识别服务。

## 部署前验证

原 133 项回归加新增共享流测试，共 134 项和 shell 语法检查通过。新增测试覆盖跨轮清空、旧身份拒绝、重复 claim 拒绝、完整帧发布、边界裁剪、异常长度、撤销及完成后拒绝追加。实际 ARM32 独立测试还验证模式 6 原样转交回调、真实唤醒撤销映射且不会恢复旧轮、超时保护只接受合法模式。

在未启动麦克风/云请求的设备独立进程中，由已保存 PCM 驱动真实旁路程序：

| 情况 | 结果 |
| --- | --- |
| 正常实时发布 seq 41 文件 | 8840 ms 候选，与此前文件实测一致；8880 ms 输入全部处理，status=ok |
| 发布 210 ms 后主动撤销 | status=invalid，reason=revoked |
| 一次灌入超过 250 ms 的积压 | status=invalid，reason=backlog-over-250ms |

证据 `neural-vad/stream-checks.txt`。后续窗口从 20 秒改为 24 秒后，重新构建，重跑共享流测试、ARM32 原生回调测试及全部 134 项回归。

## 现场第一轮：只能判断没有早停

seq 46，目录 `trial.neural.6.k7bgSt`，dialog `ecb3bafb02b0654a9f5aec19e4d4c7b8`。用户确认只说一次、停顿约 1.5 秒后轻声补充、随后安静且无报错/其他人声。

小米文本包含完整的“苹果的种子为什么会发芽请用一句话回答”，最后 ASR end offset=18640 ms。20 秒窗口只剩约 1.36 秒尾部，低于设定的 2 秒静音，因此整段没有候选结束。此轮不算判停速度通过，也不算噪声拖延失败；没有可用的足够长句后观察区间。

旁路处理 2000 帧、无无效标志；CPU 3608.603 ms、RSS 26060 KiB、最大单次推理 9.371 ms、峰值排队 20 帧。CLI 与旁路均 0，SDK 明确 `client process Dialog.Finish done`。

## 现场第二轮：得到完整句后的唯一结束候选

seq 47，目录 `trial.neural.6.2RKIXQ`，dialog `0d556467574d875eec19b3fb4a83de9c`。用户再次确认只说一次、按要求停顿并轻声补充，随后安静，无报错和其他人声。

| 观察项 | 结果 |
| --- | --- |
| 小米完整 final | 苹果的种子为什么会发芽请用一句话回答 |
| ASR begin / end offset | 10380 / 14840 ms |
| 神经网络首次触发 | 10540 ms |
| 唯一候选结束 | 16970 ms |
| 候选距 ASR 最后 end offset | 2130 ms，作为约数参考 |
| 原样处理 PCM | 2400 帧 / 24 秒，768000 字节 |
| 旁路状态 / CLI | ok / 0 |
| SDK 完成 | 同 dialog 的 Dialog.Finish 被正常消费，无本轮超时错误 |

没有开口前的候选，没有在中间停顿处提前结束，也没有尾部重新触发。神经网络回溯标记的语音段 end=14960 ms，与其实际发出候选的 16970 ms 是两个不同概念。评价是否早停用后者，不可用回溯边界假称已提前知道结束。

同一录音前 20 秒在音箱独立文件程序重算，首次触发 10540、唯一结束 16970、回溯边界 14960 ms 全部一致。这证明本轮旁路计算与文件计算相符，不把 EOF 或后来的 final 倒灌成更早决定。证据 `live-prefix-recheck.txt`。

## 并发资源与限制

seq 47 在原生 ASR 同时运行时 CPU 4381.826 ms / 24 秒，约单核 18.3%，RSS 25528 KiB（约 24.9 MiB）。最大单次推理 11.545 ms；峰值排队 20 帧（200 ms），低于失效门槛 25 帧，但余量有限。所有 2400 帧都被处理，未报告旁路丢失/失效。

不能说所有帧都在 10 ms 内完成；也不能从总计数证明积压只发生在起始阶段。本轮没有并发播放、抢占等全负载实测，后续需要补队列峰值发生时刻/持续时间，以及真实唤醒打断与异常回退验证。

这个结果支持下一步在独占实验会话中验证“候选实际触发结束”，不支持直接接管所有生产请求。还有不同说话人、距离、持续非人声与旁人说话等泛化边界；固定 2 秒也不可能容纳任意长停顿。当前能力是音箱本机的人声/静音判断，不是语义上确定用户已说完。

原先的 LLM 播放卡顿仍未由本试验定位，不归因于网络或本次新 VAD。

私有证据目录为 `tmp/asr-shadow-20260918/neural-vad/`；两轮的原始 PCM、共享区、日志和逐轮 `audit.json` 均只保留在忽略目录，不提交。最终 24 秒版实验库 SHA256：`c0f7ca2cf53249dbd0b1528a1fc7fe82aa810be94f9d138c70a7884fb1c76e94`；运行包 manifest SHA256：`a99f5441ff26bdeab74c9493be17e49199f6aa1a5415cf882add87bdcab2fde9`。

## 恢复结果

两轮后都恢复了原 init；最后逐项清理神经网络测试目录中的运行库、模型、派生片段和独立测试工具，保留原有 trial 证据。最终 native_asr healthy，mipns 880 / aivs 813，sequence 47，final=1/finished=1。init 与客户端 SHA256 均与试验前一致，进程未加载实验库，无 neural_shadow 后台进程、armed/capture.armed/timer.armed 或 busy 残留。证据 `shadow-final-status.txt`。

本机保留初版 `shadow-runtime.tar` 和最终版 `shadow-runtime-24s.tar`，后者逐项对照当前 manifest 后重新打包，避免下一次误用旧的 20 秒缓冲区 ABI。第三方依赖和包均未提交仓库；正式分发方案尚待决定。
