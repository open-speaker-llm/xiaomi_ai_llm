# 2026-09-17 晚间现场基线

结论：句中停顿可以复现首轮云端提前结束收音。前端 PCM 中存在后半句话，原生云端 final 和 LLM 输入却只有前半句。此轮证据把问题定位到云端收音结束与客户端直接提交的衔接，不能靠延后读取同一条 final 恢复已经停止上传的后半句。

## 方法和有效范围

同一 S12A、同一部署客户端、同一句月亮问题。临时 tap 旁路读取前端处理后的 16 kHz 单声道 PCM，同时记录云端指令、原生状态与客户端日志。没有改变 ASR VAD 参数、注入音频或部署客户端修正。录音在 Mac 用本地 Whisper small 复核，不发送到转写服务。

四份 30 秒采样中，一份连续说话、一份约 1 秒停顿口令、一份约 2 秒停顿补采可用于比较；另一份开始录音晚于唤醒，排除。1/2 秒是给参与者的口令，并非实测静音时长，不据此宣称云端具有固定 1 秒或 2 秒阈值。离线转写的词时间戳会跨过静音，PCM 时间戳也是消费者观察时间，不作为精确声学边界。

| `trial.2vI4uz` | 停顿补采 | 21:56:27.945 / 27.948 | 21:56:28.907 | final 与 LLM 均止于“问问DEEPSEEK为什么月亮”；PCM 离线转写包含完整后半句及“请用一句话回答” |

补采的系统日志先出现 `SpeechRecognizer.StopCapture`，再出现 `cloud-vad-end`，final 为前半句，随后 21:56:28.054 原生报告 `asr send end`。前端采样继续成功直到窗口结束。后半句有录音而没有进入本轮云端 final；不支持把这两次提前提交归因于 LLM 生成或前端麦克风停止采集。

两次截断都已产生 `final=true`，因此客户端仅接受 final 的防护虽可修复另一个 partial 提前提交问题，无法单独修复这次云端判停。也不能从几份样本推断所有截断都具有相同原因，或排除网络对云端判停时序的潜在影响。

## 方案约束

1. 需要区分“ASR 这一段结束”和“用户本轮说完”。单纯等 final 或延迟 LLM 请求，不会自动恢复已经停传的语音。
2. 优先验证现有原生 ASR 能否由本地可靠决定结束并完成协议闭环，复用现有 PCM 和识别服务以控制成本。先验证禁用云端提前判停、持续上传、正确发送结束、完整 final、Finish、取消与真实唤醒交接，再决定本地判停算法。
3. 尚未验证以上控制链可行。`enable_local_vad` 为固件空实现；外发结束报文也不能只凭枚举猜测。必须同时覆盖长句超过先前约 9 秒截断位置，以及网络异常/超时退出，不能直接部署“关闭云端 VAD”。
4. 若原生协议不可控，再比较本地完整收音后转写与多段 ASR 合并方案的延迟、识别成本、状态复杂度。不给特定呼叫词添加例外，也不增加一次 LLM 调用来判断每句话是否完整。
