# 常驻实验接入与实际回滚验收

接续 [常驻管理验证](native-resident-20260919.md)。本轮在真实麦克风、原生小米识别和实际 LLM 路由中运行最新常驻管理版本，并执行完整设备回滚。所有修改仍为临时实验，结束后恢复日常版本；没有安装开机服务。

## 准备与本次修正

复核恢复脚本时发现：服务 init 命令返回，不等于进程已退出或新服务已健康。`native_route_restore.sh` 现在分别等待全部旧原生进程消失和日常服务健康，每 200 ms 检查一次，最多 10 秒。超时仍拒绝继续，不移除恢复标记；没有将失败当作成功。

新增测试覆盖延迟成功及持续失败的有界等待。完整回归 196 项，195 通过、1 项 Linux CPU 信号测试在 macOS 跳过，耗时 131.318 秒；该跳过项上一阶段已有 ARM 实测证据。shell 语法、ARM 严格编译通过。按清单校验全部临时文件后，先切换临时客户端，再装载原生探针，最后启动常驻管理；客户端恢复期限 600 秒，探针 540 秒，管理器 360 秒。

## 实际回滚与 B：日常报时

确认 IDLE 后执行完整 route 恢复：停止实验管理器和客户端，停止两个原生服务，撤下 overlay，归档旧 `instruction.log`，再启动日常原生服务与旧客户端。

归档前后旧日志 SHA256 都是 `357074a3cf67d21a64bda2ccaff1da3427101121d17278e65df4dc59fbbf3fab`；归档目录带 `native-writers-stopped` 边界记录。实际输出 `ORIGINAL_CLIENT_RESTORED`，日常客户端 PID 585，新 mipns 434 / aivs 390 健康，实际映射仅有原 `/data/native_asr.so`，无实验 probe。手动 stop 的管理器输出 `stopped=1`，其 rc=1 不是判停成功码，也不是本次恢复失败；恢复入口依据停止锁与完整恢复流程判断结果。

恢复后用户正常连贯地问一次“现在几点了”，没有刻意停顿。新 dialog `319fc733e0071e349ebb92ad36f056b2` 获得完整 final、原生 Speak“现在是晚上11点08分”和 Finish。用户确认正常报时，没有再次听到月亮回答或其他异常。客户端的“3s 未拿到新结果，暂不 fallback”是既有原生回答路径，未触发 LLM，不能单独当作失败。

恢复前后及 B 后历史文件列表完全一致，没有产生第二条 LLM 会话；本次月亮历史内容也保持不变。原客户端与两个 init 文件哈希均与接入前一致。这个样本证明正常问答结束后的真实回滚有效；不替代播放中强制回滚或所有并发故障情形的现场证明。
