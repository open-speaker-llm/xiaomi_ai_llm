# 室外非人声误检与候选判停成本

本轮只分析已授权保存的 seq 41/42/43 PCM。算术与 VAD 不生成文字；原文本、首个 partial 到达时间及 ASR 音频位置来自当时的小米云端结果。没有 Mac ASR、新服务、新麦克风采集或 LLM 请求。所有文件型 VAD 对照在音箱独立进程运行；生产 ASR 未加载这些候选。

## 人工标注的边界

用户听了 seq 42 的 14.5–20 秒原幅度片段，明确确认是室外声音、没有人说话。这将此前的“声源未知”缩小为该片段的非人声误检；不能由此标注更早的帧，或断言 seq 43 的尾部也只有室外声。现有轻量 VAD 将该尾段反复判为语音，最终 last_voice=19950 ms，20 秒 hard-limit。

## 自适应能量门槛：有改善，未采用

`noise_vad_pcm.c` 使用原样 PCM 的 libfvad mode 1，再以两级 250/500 Hz 高通后的能量作附加门槛。只过滤判断，不修改送云音频。背景参考取候选背景帧的 75 分位，至少 0.5 秒才启用，冻结后不继续学习说话音量。参考无效则回退原 VAD。能量门槛分别为背景功率的 2/4/8 倍，约 +3/+6/+9 dB。

第一种背景候选仅采用首个非空 ASR 到达前原 VAD 判无语音的帧。seq 42/43 只有 34/27 帧，不足 50 帧，均回退到原来的 hard-limit；这说明“只向原 VAD 学背景”会被同一误检限制。

第二种候选缓存开头能量，**到首个非空 ASR 实际到达时**，才读取该 partial 报告的 begin offset，选取其前方且留出 500 ms 的前缀；不足仍回退。不使用未来 final 文本。quiet 也在首个非空 ASR 到达后才允许触发，避免用户尚未开口就结束。到达时间映射到 PCM 轴仍是近似，前缀也不保证没有未识别的人声；这是离线推演，尚不是已验证的实时起始策略。

| 样本 | 原判停 | 250 Hz / 2 倍 | 250 Hz / 4 倍 | 250 Hz / 8 倍 |
| --- | --- | --- | --- | --- |
| 正常 seq 41 | 8870 ms quiet | 8740 ms | 8720 ms | 8720 ms |
| 轻声续说 seq 42 | 20000 ms hard-limit | 18350 ms | 15670 ms | 15030 ms |
| 问题后揉纸 seq 43 | 20000 ms hard-limit | 12710 ms | 11500 ms | 11490 ms |

seq 42 最后 ASR end offset=14040 ms，仅作为语音结束位置的参考，不当作精确真值。2 倍门槛仍晚约 4.31 秒；8 倍虽然更快，却过早把后半句部分能量排除，必须继续检查轻声余量。

CPU：20 秒 PCM 的 VAD 加能量分析约 40 ms，单核计算量约实时的 0.2%；不是整个服务或整机负载。证据：忽略目录 `noise-floor-results.txt`、`noise-prefix-results.txt`。

## 合成轻声压力测试

在 seq 42 的 12–14.5 秒，把原声进一步衰减 6/12 dB，并混入同一录音开头 1–3.5 秒背景，权重为 `1-gain`。这只是固定输入的压力探针，不是假称新的现场测试，也未验证小米云在这些合成输入上能否识别。

- 衰减 6 dB：500 Hz / 8 倍在 13020 ms 已结束，早于原后半句结束位置；250 Hz / 2 倍仍到 18350 ms。
- 衰减 12 dB：250 Hz / 4、8 倍在 13030/13020 ms 结束；500 Hz 三组均在 13200–13240 ms 左右结束。250 Hz / 2 倍保留到 15030 ms。
- 正常样本裁去前 4.9 秒，模拟开口前只有约 0.2 秒可用背景：所有候选都正确放弃背景校准并回退原 VAD，没有凭不足的背景设置门槛。这里只验证回退，不代表所有立即开口场景通过。

因此不选强门槛上线，也不把保守参数在几个样本上通过当作普适修复。证据：`noise-stress-results.txt`、`noise-fixtures/manifest.json` 和派生 PCM（均不提交）。

## 本机神经网络 VAD：初始兼容性检查

为比较更能区分人声与环境声的候选，取得官方发布的 Silero 16 kHz ONNX 模型，以及 sherpa-onnx 维护者提供的 ARM32 v1.10.36 预编译包。模型约 629 KiB，但选定通用运行库还包含约 10 MiB ONNX Runtime 和约 3.9 MiB C API 库；磁盘大小不等于运行内存。

对完整下载包的 ELF32 `.gnu.version_r`、`.dynsym`、`.gnu.version` 做只读分析，确认不是仅凭字符串猜测：

- C API 依赖 `log/pow/exp@GLIBC_2.29`、`expf/logf@GLIBC_2.27`。
- ONNX Runtime 还依赖 `fcntl@GLIBC_2.28` 及上述较新数学符号。
- 音箱用户态为 ARM32、glibc 2.25；aarch64 内核不等于可直接加载 aarch64 用户态库。

这个预编译包不能直接在现系统上用。初查阶段没有将它装入音箱或替换系统库，当时尚无设备资源实测。后续通过独立加载器和配套库完成了隔离文件测试，见 [本机神经网络 VAD 实测](neural-vad-20260919.md)。这解决了本次评估的运行条件，尚不表示可以把这些库加载进 glibc 2.25 的原生进程。若集成到原进程，需要针对现有 ABI 交叉编译；若采用本机子进程，还需验证隔离、生命周期及通信开销。两者均不增加外部识别服务。

最新 v1.13.8 包下载超时，文件不完整，未作为可用软件或兼容性证据。v1.10.36 完整包已成功解压，匹配同版本 C API 头文件。兼容性证据保存于忽略目录 `neural-vad/elf-compatibility.json`。

来源：[Silero VAD 模型说明](https://k2-fsa.github.io/sherpa/onnx/vad/silero-vad.html)、[官方 ARM 嵌入式构建说明](https://k2-fsa.github.io/sherpa/onnx/install/arm-embedded-linux.html)、[维护者 ARM32 构建包](https://huggingface.co/csukuangfj/sherpa-onnx-libs/tree/main/arm32)。

## 当前决策

普通音量、停顿后的轻声和非人声背景必须一起评估。简单延长静音时间只缓解早停，不能解决噪声不断重置计时；简单提高门槛则可能重新造成轻声截断。本页的能量门槛候选不投入实际判停。后续 Silero v5 保守配置具备进入旁路观察的依据，但仍未部署生产；资源实测与限制见上述后续记录。

本轮 133 项回归、shell 语法及 `git diff --check` 通过；新增背景参考测试覆盖最短校准量、冻结、门槛和无效输入回退。最终只读核查 native_asr healthy，sequence 仍为 45，mipns 2018 / aivs 1953；两进程均未加载实验库，armed/capture.armed/timer/busy 不存在，init 与客户端哈希保持不变。证据 `noise-final-status.txt`。这些检查不代表候选的现场准确率通过。
