# 同一模型跨轮接管与真实打断

接续 [重置等价性验证](neural-reset-20260919.md)。已把单模型复用接入一个**最多四轮、最长 240 秒**的临时控制器，并完成一次真实“旧问题未说完 → 再次唤醒 → 带停顿报时”的现场验证。新问题实际进入本地判停，模型进程没有退出重载。本阶段仍不是全天常驻版。

## 实现

- `native_wake_pool.c` 保留一个直接子进程 `neural_pool`，在发布 READY 前准备四份不同身份的 PCM、decision 和 receipt 映射。约 3 MiB 的 PCM 空间有固定上限；不并行加载第二份模型。
- `native_pool.h` 保存有界代际计划及终止快照。正常新唤醒在原生回调、原有锁内撤销旧映射并认领下一份预备状态，随后原生 prepare 即可带上新一轮的随机标记。回调里不做推理或等待模型加载。
- `neural_pool.c` 依次处理这些独立输入区，使用已验证的 `nm_begin` / `nm_frame` 重置适配器。每轮收到的真实 PCM 仍原样、一次进入小米上传路径；临时重置样本仅存在模型内部。
- 每轮成功通过独立 receipt 确认，核对 nonce、owner、observer、消费帧数以及原生 quiet / final / Finish，之后才能把该轮 journal 从 pending 变为 quiet。单纯“模型进程还活着”不构成成功依据。
- 新旧轮使用相同 owner 和 deadline，所以额外把 nonce 纳入原生序列化的线程局部关联条件；旧 unpack 不能因为进程复用就继承新轮身份。旧 proposal、旧 final、取消记录均不能放行新问题或旧残句。
- 新入口为 `run_native_wake_session.sh pool [秒数]`，默认 180 秒，最多 240 秒、四个代际。沿用 session / watcher 内核锁及本地 stop socket；原 restore 入口可以停止新控制器。取消也占用一个预分配代际，这是本阶段的资源边界。

预备区只解决有限轮数内的交接；槽位耗尽或超时后控制器结束并恢复原生处理。每个代际的映射只用一次，未实现循环复用槽位。

## 独立验证及发现的竞争

主机用实际控制器、模拟 helper 验证连续取消后的完成确认、模型死亡、控制器被强杀后的恢复、预加载期间停止和现有 stop 入口。音箱独立进程用真实模型按实时速度回放已有 PCM，连续运行“取消 → 完成 → 取消 → 完成”，始终同一 owner / observer。正常两轮均在 3940 ms 产生候选；复位 10–11 ms，最大积压一帧。两条取消记录保持 pending，两条完成记录为 quiet。

首次完整回归发现最后一轮的 helper 退出与控制器完成确认竞争：receipt 已发布，helper 立即退出，控制器仍需要确认其存活而拒绝最后一次退役。现已让 helper 等待控制器把最后一代标为退役后再退出；修正后的 173 项回归、真实 ARM 四轮联动均通过，然后才进行以下现场测试。

实际 ARM 原生回调测试也通过：四次新唤醒同步认领不同输入区，前代输入失效；旧 proposal、旧线程关联和迟到 final 被拒绝；连续取消没有旧 EOF。测试是独立进程中的模拟回调，不向真实服务发送问题。

**17 ms 是首帧内的模型重置耗时，不是端到端应答时间。** 原生同步接管发生在新 prepare 前，而模型在新音频到来后完成重置。此现场样本证明该路径不再等待每轮约 1.9 秒的模型重载，不代表所有唤醒/异常情况都已有相同延迟保证。

## 现场后的空输入边界补充

审查发现另一条路径：某轮因原生忙碌等原因未能认领 PCM，其输入区仍为 WAIT；随后新唤醒切到下一代，单模型 helper 会停留在旧 WAIT 区。

先用新增测试复现失败，再修改 `np_advance`：对于取消/失败的旧代际，即使它尚未被认领，也必须校验身份并显式撤销输入区。这样 helper 才能转到下一代；没有音频的旧轮不会产生 journal 或成功 receipt。

修正后 **174 项主机回归通过（87.200 秒）**，shell 检查、ARM 严格编译通过。独立音箱真实模型序列“空输入跳过 → 正常完成 → 语音中取消 → 正常完成”通过：两次正常候选仍为 3940 ms，复位 7 / 11 / 11 ms，最大积压一帧，只有语音中取消留下 pending。

这项现场后的空输入补充没有再做真人测试；前述现场使用的是补充前构建。相关正常路径已经现场验证，新增边界由主机与独立 ARM 实际模型覆盖，不能混写成最终构建的全部边界都已现场验收。
