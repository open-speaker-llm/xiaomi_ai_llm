# 音箱本机神经网络 VAD 文件测试

结论：Silero v5 在 S12A 独立进程中可运行，保守 threshold=0.25 的候选在本次有限样本中保住续说，并缩短室外声、纸张声引起的拖延。threshold=0.5 在最弱合成续说中提前产生结束，因此不采用较快的这一配置。生产判停没有改变。

## 隔离运行条件

用户态 ARM32 / glibc 2.25，内核 4.9.61 aarch64，4 核，约 242 MiB 内存。没有替换 `/lib`、改 init、改 `/data`、启动常驻服务或新开网络接口。

临时测试目录 `/tmp/xiaomi_neural_vad_20260919` 使用自己的加载器、glibc 2.36 和 libstdc++，仅由一次性文件程序显式加载。原服务仍使用原系统库。测试进程设置 core=0、虚拟地址上限 96 MiB、单进程 CPU 时间上限 20 秒。每轮完整处理原 PCM，所有结果在本机产生；Mac 只构建、拷贝并整理结果，不做 ASR。

组件固定为：

- sherpa-onnx ARM32 v1.10.36，C API 头文件与库同版本，内含 ONNX Runtime 1.17.1。
- Silero v5 官方双采样率 ONNX 文件，2,313,101 字节，SHA256 `6b99cbfd39246b6706f98ec13c7c50c6b299181f2474fa05cbc8046acc274396`。
- Debian ARMHF `libc6_2.36-9+deb12u7`，deb SHA256 `2e837cab99a0dabcc1672b19829c15f8b16b61e52196d97513bb179bf41a6b03`；`libstdc++6_12.2.0-14+deb12u1` 提供 C++17 aligned-new 符号。

两个明确失败保留证据：最初缺少 aligned-new 符号，加入进程专属 libstdc++ 后解决；629 KiB 的精简模型是三输入三输出，而旧版包装层接受的原始 v4/v5 形状不同，拒绝加载。最终测试采用匹配的 v5，不把精简模型大小或尚未运行的 INT8 性能算入成本。失败日志 `first-run.txt`、`first-run-with-cxx.txt`。

## 测量方式

`neural_vad_pcm.c` 只接受本地库、模型、PCM 路径和门槛。16 kHz、单声道、16-bit PCM，最长 20 秒，每次送 160 点（10 ms），模型窗口 512 点、1 个推理线程、最短语音 120 ms、静音 2 秒。最大语音段设置 30 秒，避免在本次最长 20 秒输入内自动切换另一组结束门槛。

记录的是流式处理中“完整语音段进入队列”的**当时**音频位置，没有调用 Flush，也没有给 EOF 补静音。继续处理剩余文件，才能发现“先错误结束，后又认出续说”的失败。没有用最终文本或未来帧来撤销更早的结束。表中首个结束才是自动判停候选，不能只选择最后一个好看的结束点。

## 保存样本对照

时间均为从文件起点累计的秒数，不是用户说完后的等待时长。

| 样本 | 原轻量 VAD | v5 / 0.25 首个结束 | v5 / 0.5 首个结束 |
| --- | --- | --- | --- |
| 正常问题 seq 41 | 8.87 | 8.84 | 8.81 |
| 停顿后轻声续说 seq 42 | 20.00 上限 | 17.26 | 16.10 |
| 问题后揉纸 seq 43 | 20.00 上限 | 10.02 | 9.99 |
| seq 42 后半句再降 6 dB 并混入背景 | — | 17.29 | 16.14 |
| seq 42 后半句再降 12 dB 并混入背景 | — | 16.17 | **13.29，失败** |
| seq 41 裁去前 4.9 秒，模拟立即开口 | 3.97 | 3.94 | 3.94 |
| 用户确认的室外非人声 14.5–20 秒，单独输入 | — | 无语音触发 | 无语音触发 |

12 dB 合成样本在 0.5 门槛下 13.29 秒已产生结束，13.74 秒才重新触发，第二段在 15.98 秒完成。如果实际按首个事件结束，就会丢后半句；不能因第二段最终能检测到而称通过。合成输入未重新送云识别，判断依据是已知保留的原后半句时间范围，不是臆造云端文字。

0.25 门槛下 seq 42 从云端最后 ASR end offset=14.04 秒到候选结束约 3.22 秒，比原上限的约 5.96 秒短；seq 43 相应由约 12.12 秒降到约 2.14 秒。ASR offset 不是人工精确标注的语音边界，只作为延迟参考。

纯室外声单独输入没有触发，并不意味着在所有上下文里完全忽略环境声。seq 42 连续输入的 0.25 候选最后语音边界为 15.248 秒，比人工确认的非人声起点 14.5 秒晚；仍存在尾部误检/迟滞。保守候选因此比 0.5 多等约 1.16 秒，不能宣称噪声问题完全消除。

## 实际开销与较旧模型比较

v5 批量文件测试：20 秒输入 CPU 约 3.20–3.24 秒，约单核 16%；峰值 RSS 约 25–26 MiB；加载初始化约 1.9 秒。v5 所需本次通用运行组件共 20,274,157 字节，约 19.34 MiB，不包含 v4、旧精简模型、录音及诊断日志。文件大小、RSS 和 tmpfs 文件占用有共享页，不能简单相加当作实际物理内存。

另用真实 10 ms 节奏喂入 seq 42（仍只读旧文件）：初始化 1885.580 ms，处理 CPU 3387.242 ms / 20000 ms 输入，约单核 16.94%；峰值 RSS 26532 KiB；最大单次处理 7.656 ms，输入到处理完成最大 7.775 ms，超过下一帧 10 ms 截止的帧数 0。候选结束仍为 17260 ms。这个结果证明该负载下能跟上节奏，不代表与唤醒、ASR、播放并发时已验证。初始化应在准备阶段完成，不能每轮唤醒后阻塞近 2 秒再开始接收。

v4 对照约单核 14%、峰值 RSS 18–19 MiB、初始化 1.05 秒，但在 0.25 门槛下正常录音开头的非目标内容触发，2.82 秒已产生一次结束，早于该轮云端语音 begin=5.1 秒；真实正常句结束到文件 EOF 时又没完成第二段。0.5 没有该早期触发，但同样未在正常文件结束前产生结束。轻声轮仍拖到 18.4–18.6 秒。相对于省下的资源，这些结果不支持选 v4 进入下一阶段。

证据在私有忽略目录 `tmp/asr-shadow-20260918/neural-vad/`：`results-v5.txt/.json`、`outdoor-v5.txt/.json`、`results-v4.txt/.json`、`realtime-v5.txt`、`final-manifest.json`。不提交录音、第三方二进制或私有日志。

## 下一阶段边界

v5 / 0.25 / 2 秒静音只作为旁路观察候选，尚不是生产配置。下一阶段需做到：模型准备好后才进入试验；按轮次清空模型状态、废弃旧数据；原样上传音频，候选只观察；真实唤醒或数据断流时撤销该轮判断；验证正常问题、停顿轻声、环境声以及与原服务并发。先观察再考虑让候选发送结束，不能把文件测试的结束事件直接接到所有原生会话。

如果进入产品实现，本机工作线程或子进程都属于音箱内部组件；无需用户另外搭服务器，也不会在 Mac 上做文字识别。原进程直载需要构建 glibc 2.25 兼容运行库；独立子进程需要验证生命周期与有界通信，并纳入同一项目的启动和恢复管理。本次独立加载器只是低成本验证路径，未选定永久分发方案。

原始的两次 LLM 播放卡顿仍是独立待查问题，本次 CPU 测量不能解释此前的播放停顿。纸张测试 SDK 完成边界超时的修正另见 `contrast-20260919.md`。

## 收尾与复现

`build_neural_bench.sh` 校验版本固定的头文件 SHA256，再以 ARM32/glibc 2.25 目标、`-Wall -Wextra -Werror` 构建文件工具。它没有自动下载、安装或部署步骤。示例（依赖目录在私有忽略路径）：

```sh
sh device/endpoint_probe/build_neural_bench.sh \
  ../asr-shadow-20260918/neural-vad ../asr-shadow-20260918/neural-vad
```

本轮实际执行 14 组 v5 文件对照、10 组 v4 对照，以及 1 次 20 秒实时节奏检查；构建和 shell 语法检查通过。原有 133 项回归是前一阶段结果，本轮新增的是独立文件程序，未再次把那组回归计为本轮新证据。

测试后逐项移除本轮临时目录中的模型、运行库、工具和派生片段，再删除空目录；未动旧试验录音。最终 native_asr healthy，sequence 仍为 45，mipns 2018 / aivs 1953，进程未加载实验库；init 和客户端哈希与试验前相同，没有 armed/capture.armed/timer/busy，也没有 VAD 后台进程。可用内存恢复到约 149 MiB，`/tmp` 可用约 96.7 MiB。证据 `final-status.txt`。本机工作区保留私有依赖和原始结果，可复核但不提交。
