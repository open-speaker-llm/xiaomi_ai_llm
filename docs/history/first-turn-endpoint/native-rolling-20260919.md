# 四个输入区循环接续与取消记录压缩

接续 [四轮单模型接管](native-pool-20260919.md)。本轮实现可选的循环补充模式，主机连续 40 轮、音箱真实模型连续 16 轮通过。每轮使用新的身份和新的映射文件；四个槽位轮换，只有一份模型。仍保留最长 240 秒的实验租约，尚未发布全天常驻版。

## 实现与边界

`run_native_wake_session.sh pool [秒数] [总轮数]`：省略总轮数时保持原四轮模式；显式总轮数支持 4–10000，秒数仍为 5–240。总轮数是预算，不是保证能在租约内完成的轮数。取消、空输入跳过也消耗一轮。

- `native_pool.h` 新增 prepared / recycling 状态、累计退役数与失败数。真正唤醒仍同步切到已准备好的下一槽，不在原生回调里加载模型或等待回收。下一槽未就绪时结束本次接管，不复用旧输入。
- `native_pool_maps.h` 统一映射生命周期。旧轮必须已经退役、模型已发布终止 receipt，控制器才分配新的 nonce、随机 tag 和文件路径。模型关闭旧映射后创建新映射；新 receipt 用 release/acquire 发布初始化完成。控制器确认新映射后才删除旧文件、设置 prepared。
- 新旧代际使用不同 mmap 对象，旧线程即使还持有引用，也无法写入新代际。槽位暂存旧快照供回收、停止及控制器崩溃后的清理使用。正常回收后固定 12 个映射文件；回收交接期间最多 7 组（21 个）文件，不能把采样时的 12 个误写为瞬时峰值。
- helper 每 50 ms 检查补充计划，在单模型的处理循环中预建后续输入区。没有新增并行模型、Mac 识别或外部服务。
- quiet 记录保留最近 32 条用于诊断；取消及失败证据必须继续拒绝迟到 final，不按年龄删除。

`native_denials.h` 把已明确退役、已取消的精确 dialog ID 放进 `routes.denied/b_<首字符>`，保留完整 ID，不使用概率过滤或过期时间。写入与逐条 journal 的删除顺序固定为：发布新 bucket → 复核原记录身份及 inode → 删除原逐条记录。客户端先读逐条记录、再查 bucket，避免迁移期间产生放行空隙。未退役、陌生、损坏或 quiet 记录不能被这条路径压缩。

每 bucket 上限 128 KiB，名字字符集最多 64 个 bucket，因此拒绝表内容最多 8 MiB（另有一个写入中的临时 bucket）；常见十六进制 ID 使用 16 个 bucket。达到上限、格式损坏或读取失败时保留原证据并拒绝继续控制，不宣称无限容量。最后一个代际及异常退出时没有完成压缩的 pending 仍保留。

## 音箱真实模型 16 轮

使用已有 `immediate.pcm`，按实时速度写入独立测试映射；无麦克风、云 ASR、LLM 或播放。真实模型只加载一次，控制器 PID 1903、helper PID 1905，连续完成 8 次正常结束、4 次语音中取消、4 次空输入跳过。

- 8 次正常轮均在累计音频 3940 ms 产生候选，完整消费 398 帧，控制器确认 quiet。
- 每次重置 7–14 ms，最大音频积压 1 帧。
- 15 次回收后采样均为 12 个映射文件；helper 58 个内存映射、3 个文件描述符，均未增长。
- RSS 从预热中的 26080 KiB 到 26468 KiB，之后 14 次采样保持 26468 KiB（约 25.85 MiB）。这是短时固定样本测量，不能证明全天或所有输入下不存在泄漏。
- 4 个语音取消 ID 已转入精确拒绝表；8 个正常结果保留 quiet；空输入不产生路由记录。
- 最后一轮为空输入取消，控制器按 16 轮预算退出。日志末尾的 `reason=deadline` 来自 helper 收到停止信号后的默认原因字段，并非等了 150 秒或正常语音失败；该轮没有成功 receipt 或放行记录。

本轮只做独立回放与模拟原生回调，没有重做真实唤醒现场。上一轮真人测试结论仍只对应前一版，不能与本轮循环压力验证混同。
