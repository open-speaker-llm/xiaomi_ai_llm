# 神经网络候选实际触发结束：独立会话验证

seq 48 已验证音箱本机的“检测说完 → 原控制器结束收音 → 小米返回完整 final → SDK 正常 Finish”链路。用户确认只说一次，在中间停顿约 1.5 秒并轻声补充，随后安静，没有报错或其他人声。实验不请求 LLM、不写对话历史，生产首轮尚未采用此策略。

## 模式 7 的授权范围

仅 `run_active.sh trial neural-end 7` 允许采纳候选。模式 6 保持只观察；两者仍有独立租约、24 秒固定上限、30 秒等待/租约与五分钟自动恢复。现场试验前先预载模型并确认精确 BOUND 与音频通路，再提示说话。

`neural_decision.h` 增加单独的 44 字节提议映射。观察进程对音频映射保持只读，只能写提议；原控制器只读提议并独占结束回调。每个映射都绑定 sequence、owner、observer，提议另包含 producer、已处理帧数、原候选帧数、单调时间和 invalid 状态。发布用原子代际计数防止读取一半的新数据。

采纳必须同时满足：

- 原有租约仍属当前进程、同一轮次/owner，处于 BOUND，未 final/未交接，armed 模式精确为 7，设备未静音。
- 观察进程仍存活，源流仍为 LIVE，提议身份与源流一致，没有 invalid 标志。
- 提议年龄最多 150 ms，已处理帧数与此刻原控制器已发布帧数**相等**，候选为非零且不指向未来。
- 在持有原有唤醒/回调锁的情况下，于实际结束前再次确认。提议若变更则跳过本次候选，不把固定上限一并取消。

观察端继续处理后续输入；再次检测到语音就撤销静音候选，故不是把第一次候选永久锁死后等控制器来读。真实唤醒、换轮、断流、积压、进程退出与失效映射都不能授权提前结束。助手程序仍无 SDK/原生控制器/网络调用，实际 `set_unwakeup_status` 和 STREAM_END 走原控制器已有路径。

这些门槛针对误用旧轮次、延迟提议和异常输入；2 秒静音本身仍是实验策略，不是对语义结束的确定判断，也不能保证任意长停顿都能继续。

## 前置证据与检查

135 项回归及 shell 语法检查通过。新增提议测试覆盖合法采纳、轮次/owner/producer/observer 不一致、过期/未来时间、未追上音频、候选撤销/未来帧、失效状态和发布中的奇数代际。额外 ARM32 独立测试验证模式 7 的实际只读映射与撤销，不调用真实结束回调。

旧 seq 41 文件以真实时间写入共享流，实际提议经同一 `nd_due` 判据后在 8840 ms 关闭流，观察器正常退出，等于原文件候选时间。没有在该前置测试启动麦克风或云请求。证据 `decision-integration.txt`。

## 资源与已知余量

CPU 3624.727 ms / 19.38 秒音频，约单核 18.7%；峰值 RSS 25996 KiB，约 25.4 MiB；最大单次推理 14.122 ms。首个峰值排队 23 帧（230 ms）发生在处理音频位置 70 ms 的起始阶段，距离 25 帧失效阈值仅 2 帧余量。新增 NEURAL_BACKLOG 日志记录刷新峰值的时刻；它不提供所有后续同峰值事件，不能据此断言后面绝无相同积压。
