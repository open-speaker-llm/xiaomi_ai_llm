## C 的独立复现与运行时修正

结合进程映射与已校验 libc 的反汇编，内核寄存器记录中的返回地址落在 `__clock_gettime64` 的 syscall 403 调用之后；失败后该函数退回 syscall 263。本机 Linux 4.9 对不支持的调用输出寄存器。模型帮助进程现在单独链接 ARM32 的 clock_gettime 实现，直接使用既有内核 ABI 263；不修改系统库、内核日志级别或原生进程。四种时钟各 100 次对照内核原始调用以及非法 clock ID 的 errno 均通过。

单独修正取时后，对同一 PCM 在第 151 帧一次集中写入 31 帧，仍可稳定复现 `reason=backlog frames=150 max_queue=31`，说明原先积压阈值本身也会拒绝无丢失、可追平的突发输入。不能将 C 全部归因于日志负担。

随后将最多可追平积压设为 50 帧（500 ms）；不跳帧、不伪造静音，不改变正常句末等待。结束资格仍要求已消费全部音频、同轮身份、新鲜度及原生端再次核验。音箱同一真实模型完成 8 轮：三轮 31 帧突发均追平、quiet 候选仍为 3940 ms；一轮 61 帧超载仍失败并拒绝路由；随后正常输入恢复；一轮静默仍拒绝路由；其余正常问题通过。共 6 次放行、2 次拒绝；该模型 PID 的 syscall 403 日志为 0。候选已构建，但独立回放不能代替 C 的真实唤醒复测。

新增私有证据 `clock-compat-build/`：`profile.maps`/`profile.syslog`、`clock-unit.txt`、`burst-before.txt`、`burst-after.txt` 和构建包。
