# LLM 连续播放时恢复原生 AEC 参考通道

用户明确要求 LLM 保持连续播放，不以停止或暂停播报代替并行唤醒。

## 故障证据

先前日志中的 `NATIVE_THINK_IGNORED_BUSY` 只表示没有转交给 LLM，不足以证明小爱原生识别也被屏蔽。原生回调透传与声学串音需要分别检查。

在已校验的 boot1 / S12A / ROM 1.76.54 上，固件 `xaudio_aec_thread` 使用 7 个平面、每平面 128 个 S16 样本的输入。前 6 个平面是麦克风，第 7 个是参考音频；参考峰值小于 10 时，分支直接复制麦克风样本，跳过 AEC 运算。依据为设备 `libxaudio_engine.so` 的符号与实际反汇编，未修改该库。

临时探针调用原 `xaudio_wrapper_recorder_read` 后只计算各平面的峰值和能量，不保存录音、不修改输入输出。相同 5 秒合成校准音的结果：

| 启动方式 | 播放时参考平面 | 结果 |
| --- | --- | --- |
| 原配置，Loopback Disable | 峰值始终为 0，活跃帧为 0 | AEC 没有播放参考信号 |
| 先 Enable，再重启 PNS 采集 | 稳定播放段峰值约 34，每秒 124–126 帧活跃 | 参考信号已进入 AEC |
| 同一采集下原生 TTS 对照 | 参考峰值 1440–1887 | 原生播放参考信号也存在 |

此前在采集运行期间临时开启 Loopback 未改善识别；本次验证表明必须在采集启动前设置。诊断结束后已解除临时探针挂载，恢复原生服务；探针和固件副本不进入仓库。

## 修改和回退

`native_asr.sh` 在已通过固件校验的设备上保存原 Loopback 值，在建立原生采集前启用参考通道；生成的 PNS 覆盖在每次启动时执行相同设置。健康检查要求参考设置已准备且当前为 Enable。

停止组件和安装失败时恢复原值，然后重启原生服务，避免恢复顺序导致采集仍沿用新路由。重复准备不会覆盖最初的设置。不存在控制项、设置失败或原值损坏时不报告健康。

没有更改 LLM 播放、音量、唤醒转交规则或原生 ASR 二进制。

## 验证

- 原基线 89 项测试通过；修复后 95 项测试及 shell 语法检查通过。新增回归覆盖原设置保存与恢复、重复准备、已有 Enable、不支持/失败的控制项、恢复顺序和安装失败清理。
- 同一段合成语音、相同播放参数，通过 ASR-only 会话比较播报串音，不进入 NLP 或家居执行。修复前 ASR 返回 11 字，9 个三字片段全部来自测试播报；修复后返回 2 字。该结果说明串音改善，不能据此声称完全消除回声或真实唤醒已验收。
- 管理脚本已安装到 boot1，`status` 返回 healthy、Loopback Enable，保存原值 Disable；客户端 PID 1003 保持运行，`native_asr.so`、客户端和已修复的 `ettsc` 哈希均未变化。
- 实机备份：`/data/native-reference-backup-20260909-092535/restore.sh`。在设备空闲时执行即可恢复本次安装前的管理脚本和参考设置。
- 用户按人工用例 P2 实测后回复“实现了”，确认播放中唤醒、家居动作及 LLM 连续播报符合预期。09:27:19–09:27:51 的播报窗口内，原生最终 ASR 依次为：09:27:24.750 开灯、09:27:29.435 关灯、09:27:33.755 开灯、09:27:38.183 关灯。家居动作依据用户反馈，日志不单独作为物理执行证明。
- 本轮 LLM 共 3 段，均首次合成成功、没有原生补播，流式总耗时 35.76 秒；结束后恢复 Master 145、Hard Mute off、IDLE，管理器 healthy。该实测中仍有 `NATIVE_THINK_IGNORED_BUSY`，说明它并不是原生唤醒失败的充分证据。`is_aec_scene` 在 0 和 1 间变化，也不应单独作为整轮 AEC 是否生效的结论。
