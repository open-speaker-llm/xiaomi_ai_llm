# S28 转 LLM 提示音验收

版本为基于 `9b7f84d` 的 S28 提交（`feat(route): 转入端侧流式大模型时播放本地提示音`）。真机验收 **未执行**。

## 准备

- 在仓库根目录运行 `./scripts/run_tests.sh`。单独检查可运行 `.venv/bin/python -m unittest -v tests.test_route_beep tests.test_tts_early_start tests.test_web_speculative tests.test_tts_stream_commit`。
- 在音箱空闲窗口按维护流程备份客户端和私有配置，安装本版本客户端及对应校验清单，再重启。内置提示音随客户端提供。使用 native + device 句级流式、24 kHz PCM 和 `LATENCY_TRACE_ENABLED=1`，保留现有音量。
- 先设 `LLM_ROUTE_BEEP=0` 采普通、搜索和追问的对照，再用默认的 `LLM_ROUTE_BEEP=1`、`LLM_ROUTE_BEEP_FOLLOWUP=0`、`LLM_ROUTE_BEEP_FILE=builtin` 重测。每次在空闲时重启使配置生效。

## 步骤与预期

1. 物理唤醒后测试两轮原生报时等原生可处理问题。应无提示音。另抽查一次未取得原生结果的轮次，应无提示音。
2. 测两轮普通 LLM 回答和一轮联网搜索。确认转 LLM 时应看到绿灯，并听到两声清楚的短提示音。记录灯效开始和第一声之间的实际间隔。搜索时其后依次是垫话和已授权正文，普通问答直接接正文。核对 `freeze_done ≤ beep_start ≤ beep_commit`，目标 `wake→beep ≤ 1.6s`。用耳听或录音确认没有残音叠加、截断、爆音或新增卡顿。
3. 比较 `wake→answer_commit` 和 `wake→filler_commit` 与关闭提示音时的对照，允许增加不超过 0.1 秒。两种配置下正文切句、垫话顺序和投机正文授权时机应一致。
4. 在同一对话中追问一次，默认不响。开启 `LLM_ROUTE_BEEP_FOLLOWUP=1` 再测追问，冻结后应响，汇总从追问起点计算。将 `LLM_ROUTE_BEEP_FILE` 指向不存在的绝对路径再测一轮，预期记录告警及 `beep=skipped`，垫话和正文照常播放。

## 失败记录与恢复

记录客户端提交、设备分区、配置开关、轮次、脱敏的 `[LATENCY]` 和三个时序打点。记录听到的残音、空档、截断或爆音，分享前移除问答原文、密钥、URL query、设备标识和 token。

设 `LLM_ROUTE_BEEP=0` 并重启客户端可恢复原播放序列。需要整组回退时，恢复备份的客户端、私有配置及对应校验清单，再重启。
