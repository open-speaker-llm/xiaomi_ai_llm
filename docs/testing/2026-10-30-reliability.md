# 第一轮可靠性修复：实际测试步骤

日期：2026-10-30。适用：包含 F01–F08 修复的代码，问题和实现范围见[执行方案](../plans/2026-10-30-functional-review.md)。主机回归为 250 项：249 通过、1 项 macOS 平台跳过。**这份说明没有完成真人验收；音箱尚未部署这批修改，可以留到之后再测试。**

## 开始前

1. 先在开发机记录 `git rev-parse HEAD`，再记录候选包版本和部署时间。不能只因仓库更新就认为音箱运行的是新代码。
2. 已安装首轮判停的音箱需按[整包维护说明](../../device/native_endpoint/README.md)准备兼容候选包和实际回滚目录。当前安装器不是任意版本升级器，不能直接覆盖客户端/共享 SO 或删包目录来套用首次安装流程。
3. 确认音箱空闲、测试环境安静。测试家控时使用原生本来就能控制、且能直接观察动作的灯。
4. 以下使用已配置的 `ssh xiaomi` 别名；地址配置见[文档约定](../README.md#文档约定)。只有完成候选版本部署后，下面的语音用例才是在验证新代码。

在开发机登录并读取设备状态：

```sh
ssh xiaomi
```

以下在音箱执行，只检查状态：

```sh
mount | grep ' on / '
sha256sum /data/native_first_client.sh
sh /data/native_first_client.sh status
```

仅对已安装的 boot1 组件执行：

```sh
sh /data/native_asr.sh status
sh /data/native_endpoint/manager.sh verify
sh /data/native_endpoint/manager.sh status
```

`/dev/mtdblock4` 是 system0，`/dev/mtdblock5` 是 system1。客户端待机、ASR healthy、判停 READY 是前置检查，不能代替实际听见声音。

## 第一组：正常使用，约 5 分钟

按顺序逐条操作，每条等播报和追问窗口完全结束后再做下一条。

| 编号 | 你怎么做 | 听到或看到什么才算通过 |
|---|---|---|
| R1 | 说“小爱同学，现在几点了” | 正常原生报时，无 LLM 抢答；结束后仍能再次唤醒 |
| R2 | 说“小爱同学，问问 DeepSeek，用一句话介绍西湖” | 听到完整回答，没有只有灯亮却不出声，也没有同一句整段重复 |
| R3 | 说“小爱同学，问问 DeepSeek，解释边缘计算和云计算的区别” | 回答覆盖完整问题，不只回答引号前的半句话。若识别日志实际出现转义引号，再确认引号后的文字完整进入请求；没有产生引号时仅记正常问句测试，不能算引号缺陷的现场覆盖 |
| R4 | 启用追问时，在西湖回答后的绿灯窗口说“那什么时候适合去呢” | 回答承接西湖上下文，正常播完；随后保持安静能退出 |
| R5 | 让 LLM 讲一段较长内容，播放中说“小爱同学，开灯”，随后“关灯” | 灯真实开关，LLM 保持连续播放；只在日志里看到指令不算家电执行通过 |
| R6 | 最后保持安静退出，再说“小爱同学，现在几点了” | 绿灯退出，原生报时正常，音量没有持续变大或被静音 |

不要为了验证这批修复临时切 boot 或刷写分区；两套系统应在各自已具备可靠维护和恢复入口时分别安排测试。

## 第二组：服务不可达后的恢复

此组只适用于 `LLM_PIPELINE=native`、`TTS_ENGINE=server`、`TTS_FALLBACK_NATIVE=1`。如果实际使用设备端 TTS，停止 Mac 服务不会触发这条路径，记为“不适用”。

1. 先确认 R2 正常。
2. 在运行可选服务端的开发机终端按 `Ctrl+C`，只停止该测试服务，不断开家庭网络。
3. 再说“小爱同学，问问 DeepSeek，用一句话介绍西湖”。应实际听到原生 TTS 播放模型回答，随后回到待机；仅恢复待机、不出声不能算通过。
4. 在开发机仓库根目录重新执行 `./start_server.sh`，重复 R2、R4、R6，确认服务恢复后仍能使用。

健康检查成功后的连接失败、已经播放一部分后的断流，以及 boot0 未启动录音的取消，需要可控故障服务。对应真人高级用例为 [E3/E4](../../tests/manual_native_first_cases.md#e3-tts-首包失败与部分播放失败)；尚未搭建隔离故障服务时明确记为“未测试”，不要通过随意断网把原生云服务一起破坏。

## 第三组：开发机可直接复验的故障用例

这些命令不操作音箱，使用本机服务和替身播放器。它们验证失败处理，不能证明音箱的声音和家电动作。

在仓库根目录执行：

```sh
./scripts/run_tests.sh
.venv/bin/python -m unittest tests.test_native_client_failure_paths
.venv/bin/python -m unittest tests.test_server_transfers_tts tests.test_tts_wav
.venv/bin/python -m unittest tests.test_native_install_recovery
```

应看到测试通过。平台跳过项需单列。覆盖连接拒绝、HTTP 502、部分音频、播放器提前退出、LLM 流未完整结束、WAV 扩展头/静音、上传路径越界和缺失恢复目录等场景。

## 失败时怎么记录和恢复

在音箱上读取本轮附近的客户端日志，保存在本机私有位置：

```sh
tail -n 100 /tmp/native_first_client.log
```

记录“用例编号、实际代码/包摘要、boot、说了什么、听到什么、灯是否动作、是否回到待机”。日志可能含完整对话，分享前删除私人文本、URL 中的凭据及密钥。

如果客户端未恢复，不连续重复唤醒。先保留状态和日志，再按[日常操作](../runbooks/operations.md#客户端)在空闲时重启客户端；需要回滚时使用该候选版本实际生成的备份。旧备份先按[启动目录准备步骤](../../device/native_endpoint/README.md#旧备份的启动目录准备)校验和准备目录，不能假设更新仓库已经修正设备中的旧脚本。
