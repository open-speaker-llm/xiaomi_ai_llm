# S29 首次提交与播放器欠载验收

版本为基于 `fe8d371` 的 S29 提交（`fix(audio): 修正首个 PCM 提交与播放器欠载打点`）。真机验收 **未执行**。

## 准备

- 在仓库根目录运行 `./scripts/run_tests.sh`。
- 在音箱空闲窗口按维护流程备份客户端，安装本提交的客户端及对应校验清单，再重启客户端。
- 使用 native + device 句级流式和已有的 `LATENCY_TRACE_ENABLED=1`。逐轮记录 `/tmp/native_first_latency.log` 的本轮汇总、`/tmp/native_first_stream/marks` 和默认的 `/tmp/native_first_dirac.log`。下一轮会覆盖 marks，播放器再次启动时会覆盖原始播放日志。

## 步骤与预期

1. 普通问答分别覆盖首段增量提交和整段提交。用首次 PCM 发布时间或该段合成结束时间，核对到 `fifo_commit1` 的差值等于 `commit1`。核对 `wake→commit1` 仍是本轮起点到首个 FIFO 提交。
2. 搜索问答覆盖内联、缓存和提前准备垫话。确认垫话先于正文，并核对垫话先提交时 `commit1` 对应该垫话。缓存垫话以触发发布为起点。正文首段仍可用 `tts1_to_commit` 单独查看。
3. 在提前打开 FIFO 的一轮核对 `player_prestart_wait` 等于首次提交减去 FIFO 打开时刻。首包等待不计为欠载。比较单次 aplay 的 `underrun!!!` 行数和报告毫秒数与汇总。若出现原生补播前后重启 aplay，及时分别保留两次日志，比较其合计。任一欠载行缺少时长时总时长显示 `-`。
4. 抽查连续追问和播放器重启后的一轮，确认日志按轮归属且听到的播报顺序与对照一致。

## 失败记录与恢复

记录提交、分区、观测开关、轮次、脱敏后的汇总、相关数字打点及欠载行。分享前移除问答原文、密钥、URL query、设备标识和 token。

可用已有的 `LATENCY_TRACE_ENABLED=0` 关闭延迟观测。需要恢复旧日志口径时，恢复备份客户端与对应校验清单，再重启客户端。
