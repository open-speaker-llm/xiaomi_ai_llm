# 微软 TTS v2 鉴权迁移与人工验收

## 故障与修复范围

设备上的旧 ettsc 在 WebSocket 握手阶段连续返回 HTTP 403，客户端逐句重试后改用小米原生播报，因此音色与已配置的 `zh-CN-YunjianNeural` 不同。LLM 回答正常不代表微软语音合成正常。

修复范围为 ettsc 鉴权实现与默认协议版本。保留男声音色、现有 LLM、原生语音识别及失败兜底。旧设备客户端会显式传入 v1，部署新二进制时也须迁移 `DEVICE_TTS_GEC_VERSION`。不能只更新其中一项。

## 人工测试

1. 等待音箱空闲，喊“小爱同学，问问 DeepSeek，为什么月亮白天也能看见？请用一句话回答”。
2. 确认能正常唤醒，回答使用原来的男声，整句播完。
3. 再问一个要求三句话回答的问题，确认各句音色一致，无小米声音插入、重复或截断。
4. 回答结束后再次唤醒，确认能继续使用。
5. 维护者查看 `/tmp/native_first_client.log` 及仍保留的 `/tmp/native_first_stream/*.attempt-*.log`：应见成功合成，无该轮 `403 Forbidden`、`重试耗尽`、`原生兜底`。原生家控本身的声音不作为微软 TTS 音色验收依据。

## 部署与回滚原则

先在 `/tmp` 运行候选程序，分别验证握手、指定男声 MP3 合成及 PCM 解码，再备份 `/data/ettsc` 和 `/data/native_first.env`。设备空闲时原子替换程序，并更新协议版本配置；重新启动原客户端加载配置。原客户端源码不随本次设备修复替换。

若验证失败，在设备空闲时停止客户端，从同一备份目录同时恢复程序和配置，再执行 `sh /data/init.sh`。只恢复其中一项会造成鉴权算法和协议版本不匹配。

- Rust 专项：11 项通过；上游独立向量核对 17 个时间点和 12 组摘要全部一致，另一个 Agent 只读复核通过。
