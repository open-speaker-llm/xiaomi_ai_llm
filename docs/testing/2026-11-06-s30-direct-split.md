# S30 直达交接、请求计时与早切验收

适用版本为基于 `65268cc` 的修正。真人与实际声音验收 **未执行**。

## 准备

- 运行 `./scripts/run_tests.sh`。确认搜索故障问法、原生域、实际 curl 启动打点、欠载窗口与逐 token 早切回归通过。
- 在 boot1 空闲时成组备份并更新活动客户端、包内客户端和校验清单。启用 `LATENCY_TRACE_ENABLED=1`。有自定义 `UNSUPPORTED_PATTERNS` 时按实际规则核对文案命中。

## 步骤与预期

1. 先复测“呼叫 DeepSeek 搜索一下最近 24 小时的偏爱新闻”和先前三条财经新闻问法。原生播报已下发时记录 `[HANDOFF] forced reason=direct`，先冻结原生再同步触发提示音与绿灯。若已被失败文案规则拦截，则沿用 early failure 交接。两种路径都应跳过 4 秒等待。
2. 测报时、音量和家控。原生指令保留在原生路径。普通自动转接的已开口否定回复仍应在确认播完后接管。
3. 对照 `native_freeze`、`llm_entry`、`llm_prepare` 和 `llm_req`。`llm_req` 在启动聊天请求 curl 前写入，联网规划、投机和正文中取最早的时间。
4. 检查垫话和正文提交前后各 100 ms 内报告的欠载。首段附近归 `prestart`，垫话后正文附近归 `gap`。保留原始报告，另列时长，窗口外仍按播放阶段计数。
5. 核对日期句“根据央视网《天下财经》和《正点财经》2026年11月6日的节目……”的切句和听感。逐 token 回归应在书名号后回退，日期保持完整。另检查 `3.14万元`、`12:30`、`GPT-5` 和 `Qwen3`。

## 失败记录与恢复

记录版本、实际听感、LATENCY、原始 marks 和 TTS attempt 日志。端侧 `first_audio_ms` 反映从发送 SSML 到收到首个音频包，包含网络往返。恢复时成组恢复部署前客户端、包内副本和校验清单。
