## 真人操作

确认已经部署对应客户端、`LLM_WEB_SEARCH=auto`，原有原生问答和追问正常。开发机使用已核对的连接方式登录音箱，在另一终端观察：

```sh
tail -f /tmp/native_first_client.log
```

1. 唤醒并说：“呼叫 DeepSeek，帮我搜一下 DeepSeek 官方搜索 API 的接口地址。”预期日志有 `[WEB] action=search` 和来源网址，回答说明来源。
2. 绿灯续听时说：“把刚才的回答缩短成一句话。”预期 `[WEB] action=answer`，没有新增搜索调用。
3. 新唤醒后说：“呼叫 DeepSeek，帮我写一篇今天的日记。”再用“解释一下光合作用”和“翻译这句话：帮我搜索最新手机价格”对照，预期均不搜索。
4. 新唤醒后询问一个可明确识别的地点是否营业，预期即使没有“今天/最新”也搜索；核对来源是否确实支持结论。
5. 查询一种实际商品的当前价格，续听时询问另一种；预期重新搜索，结果对应新对象。没有说清对象时应先追问。
6. 提供具体公共网页地址并要求总结，预期 `[WEB] action=fetch`。语音识别不便准确输入网址时，此例保留为独立文本接口验证，不把错误 ASR 地址当作读取功能失败。
7. 原生开灯、调音量、设闹钟、天气、报时按既有 M1/M2/M3/B3/F1/F2 流程复验，预期保持原路由与并行家控行为。记录实际动作和听觉。

故障提示由主机确定性注入覆盖，不必为现场测试改坏真实密钥。C1 后自然遇到超时或空结果时，预期按重试策略先输出至多一次“搜索中，请稍等。”，随后说明未联网并照常回答，不把模型记忆说成已查结果。`LLM_WEB_FALLBACK=fail` 才只播固定不可用提示；规划 401/402/403 输出鉴权或余额提示。这些提示和垫话都不进入历史；下一次正常提问仍可用。记录问题、时间、日志行为、实际声音、来源支持情况和异常，避免只记“测试通过”。

## 2026-11-06 提前准备实验的补充预期

默认 `DEVICE_TTS_EARLY_START=0` 时继续沿用上述预期。只有与 `DEVICE_TTS_PERSISTENT=1` 配套启用时，垫话会在 LLM 路由时静默预合成，确认搜索/抓取/重试后才独立发布 PCM；普通回答不播垫话，正文和历史不包含预备垫话。此时垫话占 0000、正文从 0001 开始，不能再用首句 SSE 是否包含垫话判断它是否播放。人工验收未执行，按[测试说明](2026-11-06-tts-early-start.md)检查顺序与恢复。

## S24 正文首段

上述联网用例使用端侧句级流式时，正文默认按与普通问答相同的首段阈值切分。垫话仍在正文之前播放一次，内联垫话和独立 PCM 槽均不占正文首段的切分额度。首段字节数与听感见 [S24 真机验收](2026-11-06-search-first-split.md)，人工用例未执行。

## S25 并行规划

端侧句级流式默认提前发起离线候选正文请求。搜索、抓取和固定错误提示用例允许多一次被取消的候选请求，候选不得进入音频或历史。旧用例需要逐一核对请求顺序时可设 `LLM_WEB_SPECULATIVE=0`。人工用例未执行，见 [S25 真机验收](2026-11-06-web-speculative.md)。

## S26 正文首段 PCM

端侧启用提前提交后，垫话仍完整且只播一次。已获规划授权的正文首段可在合成结束前写入 FIFO，后续正文段继续等整段合成。人工用例未执行，见 [S26 真机验收](2026-11-06-first-pcm-commit.md)。
