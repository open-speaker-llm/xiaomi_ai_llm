# S28c 预热与欠载归类验收

适用版本为基于 `a493272` 的 S28c 修正版。真人与实际出声验收 **未执行**。

## 准备

- 运行 `./scripts/run_tests.sh`。在音箱空闲时成组备份并替换活动客户端、包内客户端和校验清单。保留当前原生组件、Master 和提示音素材。
- 启用 `LATENCY_TRACE_ENABLED=1`。用录像对照实际亮灯、提示音和首段语音。

## 步骤与预期

1. 测至少三轮早期失败转 LLM，核对 `beep_commit − beep_start ≤ 0.10s`，`|beep_commit − led_green| ≤ 0.15s`。`beep_device_spawn` 应在路由前，`player_spawn` 应在 `beep_commit` 后。时钟同一刻度时按打点记录顺序判定。`player_fifo_open` 要早于第一段语音 `fifo_commit1`。
2. 分别测普通回答和搜索垫话，复核语音接入和最多 100 ms 的淡出。记录实际出声、`wake→filler_commit`、`wake→answer_commit`，与同题旧版对照。
3. 复测原生成功、无结果、已下发的原生否定播报和提示音关闭，检查预热取消、原生播报完整性和关闭提示音后的顺序。
4. 对照欠载原始报告。首段语音之前或紧邻首段提交且时长匹配空等的报告归 `prestart`，时长记入 `player_prestart_underrun_ms`。时长不匹配的首段后欠载仍计入 `player_underrun`。

## 失败记录与恢复

保存版本、`[LATENCY]`、原始 marks、aplay stderr 和录音。提示音可通过 `LLM_ROUTE_BEEP=0` 临时关闭。回退时恢复备份的两份客户端及对应校验清单。
