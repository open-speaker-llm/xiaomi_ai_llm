# 当前能力与验证范围

本页区分历史设备验收与最新源码的主机验证。**设备能力依据截至 2026-09-20 的验收记录**，不是对任意设备的实时检测；2026-09-21 的文档重组、2026-10-30 的源码修复和功能增强均未重新连接音箱或进行实机验收。部署方法从[上手路线](getting-started/bringup.md)进入。

## 已经形成的使用闭环

原生小爱处理日常指令，需要开放问答时由音箱直连 LLM，合成语音播放，之后可在同一上下文中继续追问。boot1 增加了首轮本地判停，用来容纳句中停顿。使用设备 TTS 和原生追问时不需要常驻 Mac，但仍依赖小米云与所选 LLM/TTS 云服务。

## 双系统能力对照

以下仅针对实测 S12A 及匹配组件。设备端通用模板与已安装实机配置不同，原生追问和首轮判停需要完成安装后启用。

| 能力 | boot0 / ROM 1.54.8 | boot1 / ROM 1.76.54 |
|---|---|---|
| 原生唤醒、报时、家电控制 | 保留 | 保留 |
| 首轮转 LLM | `domain/action` 与失败文本辅助 | 提问触发词或失败 `Speak` 文案 |
| 失败播报拦截 | think 阶段预冻结播放器 | 匹配固件的提前拦截及 C guard 后备监听 |
| 音箱直连 LLM、设备端 TTS | 可用 | 可用 |
| 免唤醒上下文追问 | 录音 + 小米文件 ASR，仍属实验方案 | 原生实时 ASR-only，已有上下文实测 |
| 追问判停 | 本地录音配置，默认 window 8 秒 | 原生 VAD，空闲约 6 秒；整轮保护超时 20 秒 |
| 首轮停顿续说 | 未接入本地判停 | 可选组件，约 2 秒句末静音、6 秒未开口退出、20 秒总上限 |
| SSH、自启动、原生 OTA 拦截 | 有配置验证记录 | 有配置验证记录；组件可随客户端恢复 |
| 停止 LLM 的播放中语音打断 | 未实现 | 未实现 |

两套系统并未完成最新版本下的同条件速度、准确率和长期稳定性对照。它们可以对同一句话走不同路由；保留原生路径也不表示小爱一定答对。

## 2026-10-30 源码修复的验证范围

基于 `e2b6fb7` 的可靠性修复完成了 8 类问题的主机验证：HTTP 播放失败清理、boot0 失败退出追问、LLM 完成与历史提交、JSON 文本完整性、TTS/WAV 错误处理、临时文件传输边界、缺失目录后的恢复启动，以及基础安装器防止覆盖判停组合包。具体证据、分工与后续优化见[功能审查与执行方案](plans/2026-10-30-functional-review.md)，逐步操作见[第一轮实际测试说明](testing/2026-10-30-reliability.md)。

最终回归为 **250 项：249 通过、1 项 Linux 专用测试在 macOS 跳过**，Shell 语法检查通过。真实本机 HTTP/curl 与 ffmpeg 格式回归属于主机证据；新增故障人工用例见 [E3/E4](../tests/manual_native_first_cases.md#e3-tts-首包失败与部分播放失败)。这些修改未部署音箱，不能把上面的历史实机验收直接转移到新补丁；BusyBox、实际出声、追问、并行家控和安装回滚仍需验证。设备上的旧备份也不会自动更新，使用时按[旧备份准备步骤](../device/native_endpoint/README.md#旧备份的启动目录准备)处理。

## 2026-10-30 第二轮功能增强

本轮在第一轮提交 `b618f38` 上增加以下功能；设备侧功能仍需以后部署候选包并单独验收。

| 功能 | 已实现的行为 | 验证边界与入口 |
|---|---|---|
| 只读诊断 | 集中检查配置、模式、固件/分区、组件、进程与状态快照、包摘要和空间；不执行配置或管理器、不联网、不自动修复 | 临时快照和只读性回归；诊断结果不等于实际收音/播放或云端可用。见[诊断参考](reference/diagnostics.md) |
| 轻量 TTS 服务 | `tts-only` 只初始化 TTS；不加载 Whisper 或 LLM SDK；统一配置端口，禁用的接口返回 503，缺少 ffmpeg 明确报错 | 全新轻量虚拟环境实际启动与本机 HTTP 验证完成，没有调用真实 TTS 云服务。见[服务端参考](reference/server.md) |
| 按模式自启动 | 读取实际音箱配置；native/device 不探测 Mac，native/server 探测 TTS 地址，server 探测服务端地址 | 主机替身进程验证；保留原有 20 秒默认等待，未重新做整机重启验收。见[自启动说明](runbooks/autostart.md) |
| 可选结束追问 | 显式启用后，追问中的五个精确结束词退出收听，不再提交 LLM；首问、否定句和引述不按子串拦截 | 默认 `FOLLOWUP_EXIT_ENABLED=0`；覆盖 native_live、native_multirounds 和本地录音路径，真人听觉未验。见[配置参考](reference/configuration.md#用结束语退出追问) |

轻量环境中确认没有安装 `whisper`、`torch`、`openai`、`anthropic`、`numpy`、`soundfile`；健康接口、被禁用接口和临时文件上传下载均使用真实本机 HTTP 检查。服务端初始化失败、单个 SDK 关闭失败及后续 provider 构造失败时，已创建的模型客户端也会逐个释放。

本轮最终执行 `./scripts/run_tests.sh`：**321 项，319 通过、2 项跳过**；跳过项分别是 macOS 不支持的 Linux CPU 信号测试和本机缺少 BusyBox 的兼容测试，Shell 语法检查通过。旧独立 ASR 服务同步修复延迟导入后的启动兼容，并覆盖初始化/运行异常清理。只读诊断的正例二进制快照另由当前原生 C 结构与 `np_valid()` 核验；这些结果均属于主机证据。

本轮逐项操作、预期现象、失败记录和恢复方法见[第二轮实际测试说明](testing/2026-10-30-operations-and-conversation.md)。结束语不提供播放中语音打断，原有“唤醒小爱控制家电，同时 LLM 连续播放”的默认行为保持；没有把历史现场验收转记到新源码。

## 仍需明确的边界

- **适配范围**：只实测 MDZ-25-DA / S12A。原生追问与判停依赖固件 ABI、组件哈希和安装基线；不是任意小米音箱的通用安装包。
- **判停与识别**：本地 VAD 判断语音活动，不判断语义完整。超过约 2 秒的长停顿仍可能结束；新唤醒时组件未就绪会保留原生收音，不能算停顿保护仍有效。追问沿用原生 VAD。
- **路由准确性**：boot1 失败分类依赖文本规则，未知文案可能漏判，相似正常文案可能误判；不保证所有文案和时序均无漏音。
- **播放体验**：并行唤醒不等于打断 LLM。历史 TTS 播放停顿仍是独立待办，近期现场无卡顿不能证明已修复。见[播放停顿记录](history/first-turn-endpoint/playback-stall-20260919.md)。
- **提示音复验**：原生追问的“欸”声隔离补丁已部署并通过设备检查；对应补丁的最终听觉复验在现有记录中仍待确认。
- **长期表现**：全天稳定性、更多噪声与距离条件、最新双系统对照仍待验证。后续固件、云端接口或 EdgeTTS 协议变化需重新检查。

实际维护前以[状态命令](runbooks/operations.md)读取设备，不把本页历史验收当作此刻健康状态。
