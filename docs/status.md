# 当前能力与验证范围

本页汇总当前主线的能力与证据。**状态依据截至 2026-09-20 的仓库验收记录**，不是对任意设备的实时检测；2026-09-21 的文档重组未重新连接音箱或进行实机验收。部署方法从[上手路线](getting-started/bringup.md)进入。

## 已经形成的使用闭环

原生小爱处理日常指令，需要开放问答时由音箱直连 LLM，合成语音播放，之后可在同一上下文中继续追问。boot1 增加了首轮本地判停，用来容纳句中停顿。使用设备 TTS 和原生追问时不需要常驻 Mac，但仍依赖小米云与所选 LLM/TTS 云服务。

## 双系统能力对照

以下仅针对实测 S12A 及匹配组件。设备端通用模板与已安装实机配置不同，原生追问和首轮判停需要完成安装后启用。

| 能力 | boot0 / ROM 1.54.8 | boot1 / ROM 1.76.54 |
|---|---|---|
| 原生唤醒、报时、家电控制 | 保留 | 保留 |
| 首轮转 LLM | `domain/action` 与失败文本辅助 | 提问触发词或失败 `Speak` 文案 |
| 失败播报拦截 | think 阶段预冻结播放器 | 匹配固件的提前拦截及 C guard 后备监听 |
| 音箱直连 LLM、设备端 TTS | 可用 | 可用 |
| 免唤醒上下文追问 | 录音 + 小米文件 ASR，仍属实验方案 | 原生实时 ASR-only，已有上下文实测 |
| 追问判停 | 本地录音配置，默认 window 8 秒 | 原生 VAD，空闲约 6 秒；整轮保护超时 20 秒 |
| 首轮停顿续说 | 未接入本地判停 | 可选组件，约 2 秒句末静音、6 秒未开口退出、20 秒总上限 |
| SSH、自启动、原生 OTA 拦截 | 有配置验证记录 | 有配置验证记录；组件可随客户端恢复 |
| 停止 LLM 的播放中语音打断 | 未实现 | 未实现 |

两套系统并未完成最新版本下的同条件速度、准确率和长期稳定性对照。它们可以对同一句话走不同路由；保留原生路径也不表示小爱一定答对。

## 仍需明确的边界

- **适配范围**：只实测 MDZ-25-DA / S12A。原生追问与判停依赖固件 ABI、组件哈希和安装基线；不是任意小米音箱的通用安装包。
- **判停与识别**：本地 VAD 判断语音活动，不判断语义完整。超过约 2 秒的长停顿仍可能结束；新唤醒时组件未就绪会保留原生收音，不能算停顿保护仍有效。追问沿用原生 VAD。
- **路由准确性**：boot1 失败分类依赖文本规则，未知文案可能漏判，相似正常文案可能误判；不保证所有文案和时序均无漏音。
- **播放体验**：并行唤醒不等于打断 LLM。历史 TTS 播放停顿仍是独立待办，近期现场无卡顿不能证明已修复。见[播放停顿记录](history/first-turn-endpoint/playback-stall-20260919.md)。
- **提示音复验**：原生追问的“欸”声隔离补丁已部署并通过设备检查；对应补丁的最终听觉复验在现有记录中仍待确认。
- **长期表现**：全天稳定性、更多噪声与距离条件、最新双系统对照仍待验证。后续固件、云端接口或 EdgeTTS 协议变化需重新检查。

实际维护前以[状态命令](runbooks/operations.md)读取设备，不把本页历史验收当作此刻健康状态。
