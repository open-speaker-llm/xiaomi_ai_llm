# Native-first 人工测试用例

文档类型：真实音箱测试清单  
适用范围：需要人工唤醒、听播报、观察日志的场景  
当前结论：主流程先测原生成功和首轮 LLM；安装原生追问组件的 boot1 必须验收 F-NATIVE，boot0 及旧 PCM 路线按各自用例测试

## 0. 测试前准备

看日志：

```sh
tail -f /tmp/native_first_client.log /tmp/native_first_events.log
```

启动成功应看到：

```text
[HOOK] mounted /bin/wakeup.sh -> /tmp/wakeup.sh.native_first_client
[HOOK] watchdog pid=...
[IDLE] 等待原生唤醒词：小爱同学
```

## 1. 主流程

### M1. 原生家电控制

说：

```text
小爱同学，开灯
```

期望：

- 家电动作成功。
- 日志出现 `domain=smartMiot` 或其他成功 domain。
- 日志出现 `success-domain`。
- 不进入 `[LLM] fallback`。

### M2. 原生天气

说：

```text
小爱同学，今天天气怎么样
```

期望：

- 播放天气结果。
- 日志出现 `domain=weather`。
- 不进入 LLM。

### M3. 原生不支持后转 LLM

说：

```text
小爱同学，呼叫 DeepSeek
```

期望：

- 对命中规则的失败文案，应转 LLM 且听不到先行失败提示；分别记录云端原话、是否转接与听觉结果，不能只记“通过”。
- 日志出现 `unsupported` 或 `non-success-domain`。
- 日志出现 `[LLM] fallback`。
- LLM 正常播报。

## 2. 播放和串台

### boot1 native_live 输入补全

- 用隔离文本种子模拟“没有真实唤醒事件、ASR 结果仅为小爱同学”：应播“我在，请说。”，提示结束后重新续听，历史不记录纯唤醒词。实际绿灯续听时喊“小爱同学”优先交还原生，按 F-NATIVE-WAKE 验收。
- 首问“呼叫 DeepSeek 帮我查一下”后停顿：应播“请继续说，要查什么？”。绿灯续听时说“OKX这家公司”，两段文本作为一个问题进入同一 session。
- “帮我查一下天气”“为什么”“那它呢”和“小爱同学，什么时候去西湖”不应被当作半句话而额外提示。
- 提示后不说话应静默退出；连续收到纯唤醒词文本但无真实唤醒事件时最多提示两次。提示合成/播报失败时不得进入收听，原音量与待机状态应恢复。
- 这是明确短句的补全用例，不代表连续长句或句中短暂停顿的收音优化已经完成；停录后的音频没有被缓存拼接。

2026-09-07：83 项本地自动测试通过；设备上 10 个短句分类用例通过，包括大小写、中文标点与完整问题透传。实机使用明确标记的文本种子触发两种固定提示，真实 TTS 播放后均开启新原生 ASR-only 会话、静默返回 124，并恢复 Master 145、非静音和 IDLE。该测试未调用 LLM，不代表用户有声补充问句的端到端听觉验收；同 session 合并由自动化用例覆盖。实测修复了旧 BusyBox `tr` 不转换 `[:upper:]` 字符类的问题，改用明确 ASCII 字母映射。

### 单句流式 TTS 故障恢复

在独立验证脚本中使用真实 `llm_stream_answer_and_play` 生产者/消费者和设备 TTS，输出三句短句；临时包装 `DEVICE_TTS_BIN`，仅让第二句失败，不修改正式配置或 `/data/ettsc`。

- 瞬时失败：第二句首次返回非零，重试成功后只播一次，三句顺序不变。
- 持续失败：第二句首次及两次重试均失败，先排空第一句 PCM，再通过原生 TTS 补播第二句；实际播放器状态经过 playing → idle 后才播放第三句。
- 任一合成命令留下部分音频但返回失败，或旧版 ettsc 报读流错误却返回 0，不得播放部分文件。
- 原生兜底调用失败、未观察到开始或播放等待超时，应结束本轮，不把完整答案写入历史；不得仍返回成功或重复整段补播。
- 验证后恢复助手、原音量和非静音状态，确认原生追问管理器 healthy、客户端 IDLE。听觉确认分别记录是否漏句、重复、重叠及原生兜底的音色变化。

2026-09-07 boot1 实机故障注入：第一句与第三句走设备 EdgeTTS，第二句三次失败后原生补播；日志观察到原生 playing → idle、`native_segs=1`、整轮返回 0，随后音量恢复，助手重新进入 IDLE。此为设备状态与执行顺序验证，不替代用户听觉验收。自动化回归 65 项通过。

### P1. 控制类短播报取消

先说：

```text
小爱同学，关灯
```

在动作已执行但短播报还没出来前，再次唤醒：

```text
小爱同学
```

期望：

- 新一轮唤醒后不应再听到上一轮“关啦/搞定”。
- 天气这类纯语音回答不应被这个策略取消。

### P2. LLM 播放期间唤醒

在 LLM 正在播报时说：

```text
小爱同学
```

期望：

- LLM 持续播放，不停止或暂停；唤醒后接着说“开灯”，观察实际灯光动作。
- 原生回调应透传，控制命令不重复送入 LLM。分别记录唤醒次数、最终 ASR、家居动作和 LLM 是否持续播报。
- 2026-09-09 已补齐 AEC 参考通道的启动配置。先确认 `sh /data/native_asr.sh status` 为 healthy、`amixer -c 0 sget 'Loopback Enable'` 为 Enable，再在长播报的前段、中段和结尾分别测试。参考信号恢复及 ASR-only 串音对照不代替真实唤醒验收，不能把唤醒或中间文本识别成功记作家居执行成功。

### P3. boot1 失败提示漏播对照

2026-09-06：首版两轮通过、报时正常；之后发现新文案漏判，修正规则并重启后，用户再次确认正常转 LLM 且没有失败提示。详情见 [实测记录](../docs/history/2026-09-06-boot1-fallback-guard.md)。

回归时在 boot1 上，用相同提问做至少两轮对照，例如“人类可能实现 AGI”（同时核对 ASR 实际文字）。

- 原生返回“这可把我难住了，看来要更努力学习了”时，应识别为失败并转 LLM。
- 启用 guard 后核对 `GUARD_BLOCK` 是否早于 shell 的 fallback，并由用户确认转接前有无可听见的失败提示；日志不能代替听觉验证。
- 再问“现在几点”，应完整走小爱原生播报，不出现新增 `GUARD_BLOCK`。
- 覆盖“被难住了诶，看来我还要再学习一下”等曾遗漏文案；云端未返回同一句时，注明仅有分类回归证据。
- 用 LLM 回答含“不会/不知道”的句子检查 busy 保护与完整播报；原生正常回答含相似词的误判另行记录。本项是回归要求，不代表本轮已经做过听觉验证。
- 持久安装后重启，确认 helper 自动启动，再重复失败提示用例。
- 测试完成应回到 IDLE，播放器不残留暂停标记；关闭 guard 或缺少 helper 时仍能执行原有 fallback。

## 4. 连续追问

先记录当前系统、识别模式和配置。boot0 使用原录音 + 小米文件 ASR；boot1 当前主线为安装后启用的 native_live。F-PCM 仅用于旧回退路线。以下用例是验收要求，不表示每项均已在当前版本完成现场测试。

### F1. 呼叫 DeepSeek 后追问

先说：

```text
小爱同学，呼叫 DeepSeek
```

听到 LLM 响应后，在追问窗口内说：

```text
Mac 电脑怎么重启
```

期望：

- 日志出现 `FOLLOWUP`。
- 如果追问打开，追问文本进入同一个 LLM session。
- 音箱日志中 TURN 递增且 session 保持一致，回答确实承接上文；仅 server 模式才需检查 Mac 的历史轮数。

### F2. 呼叫 DeepSeek 后不说话

先说：

```text
小爱同学，呼叫 DeepSeek
```

LLM 播放完成后保持安静。

期望：

- 不应凭噪声触发追问。
- 不应自动调用 LLM。

### F-PCM. S12A boot1 处理后 PCM 连续追问

旧回退路线，仅在匹配固件、采样组件与 Mac ASR 均安装后开启；不要与 native_asr 管理器同时加载。适配与证据见 [2026-09-06 记录](../docs/history/2026-09-06-boot1-pcm-followup.md)。

1. 暂停电视等背景人声，唤醒后说“呼叫 DeepSeek，用一句话介绍杭州西湖”。
2. LLM 回答结束、绿灯常亮后，8 秒内直接问“那什么时候适合去呢”，不再说唤醒词。
3. 应回答西湖的适宜季节；核对同一个 session 和没有新的原生唤醒事件。
4. 回答后保持安静；应过滤空/低置信度音频，恢复 IDLE，正常退出不闪错误灯。特别留意绿灯熄灭前后是否漏出原生失败提示。
5. “退下”“不要再讲了”等结束语不作特殊拦截，允许 LLM 自然回应后再等待下一句。
6. 退出后再喊“小爱同学”问时间，确认播报正常，Hard Mute 回到会话清理前的状态。
7. 音箱重启后，确认 PCM tap、客户端、guard 自动启动，再重复 1–4。

本项不能用“录到了声音”或“出现 ASR 文本”单独判成功；须区分原生再次唤醒、LLM 回声和真实追问。Mac 服务离线时首轮 LLM 仍可使用，追问应超时退出，不能卡住播放器。

### F-NATIVE. boot1 原生 ASR 连续追问

安装 [native_asr 组件](../device/native_asr/README.md)，使用音箱直连 LLM 与设备 TTS，停止 Mac ASR 服务并确认其端口不可达。

1. 正常唤醒，说“呼叫 DeepSeek，用一句话介绍杭州西湖”。
2. 回答结束、绿灯亮起后，不喊唤醒词，直接问“那什么时候适合去呢，也用一句话回答”，再直接追问“需要门票吗”。
3. 核对每轮新 dialog 的 `ASR-only ... disabled=NLP,TTS`、final 文本与相同 LLM session；回答应承接西湖上下文，不能只凭有 ASR 文本判断成功。
4. 听觉确认每次续听没有多出的“欸”或小爱回答；组件日志应有 `cue silenced`。正常首轮唤醒提示音保留。
5. 保持安静，确认空 final/Finish、返回 124、客户端回到 IDLE，Hard Mute 和音量恢复，再正常唤醒问时间，报时完整。
6. 重启音箱后重复，确认组件自动加载，无需 Mac 服务或手动启动。

可另在续听中重复同一句问题，确认仍作为新一轮处理；“退下”“不要再讲了”等普通结束语不设特殊拦截。播放中打断不属于已实现功能。完整同条件 boot0/boot1 速度、准确率和长期稳定性对照尚未完成，不能用一次成功代替全部回归。

## 5. 异常恢复

### E1. Mac 服务端不可达

停止 Mac 服务端后说：

```text
小爱同学，呼叫 DeepSeek
```

期望：

- 原生失败播报仍尽量被拦截。
- 音箱直连 LLM + 设备 TTS + 原生追问应继续工作，无需 Mac；选择 server LLM/TTS 或旧 Mac ASR 时才应出现相应服务不可达与降级/退出。
- 客户端最终回到 `IDLE`。

### E2. hook 恢复

手动卸载 hook：

```sh
umount /bin/wakeup.sh
```

期望：

- watchdog 重新挂载 hook。
- 后续唤醒仍能进入 native-first。


## F-NATIVE-WAKE：追问窗口交还小爱

1. 让 LLM 回答一句话，等待播完并进入绿灯续听；再喊“小爱同学”，等原生应答后说“关灯”。应执行家居控制，不出现 LLM 回答或新 LLM 历史。
2. 重复并连着说“小爱同学，开灯”。检查真实唤醒交接，原生结果不带 ASR-only 的 NLP/TTS 禁用上下文。
3. 对照不喊唤醒词、直接追问“那什么时候去呢”，仍应进入原 LLM session。
4. 静默退出，检查音量恢复、Hard Mute 关闭；再普通唤醒查询时间。
5. 检查 `physical wake handoff seq=…` 与 shell 的 `physical wake -> native handoff`。旧追问结果不得进入 LLM；交接后不得再执行旧会话的 stop/reset、静音或 led_off。

自动测试包括真实回调函数的 18 个状态/事件组合、控制程序返回 125 并拒绝旧文本、shell 清理顺序，以及设备 ABI 下旧 StopCapture/Finish/Abort 隔离。用户有声家居控制仍须按以上步骤实测。
