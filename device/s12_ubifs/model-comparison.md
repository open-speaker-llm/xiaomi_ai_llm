# S12 与 MDZ-25-DA / S12A：设备差异及连续追问实验

这是一份对**两台具体设备**的记录，不是按外观判断型号的指南，也不是可直接运行的安装教程。S12 是系统报告的硬件代号；本次没有核实该设备的零售型号。S12A 对应的零售型号为 MDZ-25-DA。本页分别标明上游文档和本次观察，不能把一台的镜像、分区号或二进制直接用于另一台。

## 硬件与系统

| 项目 | MDZ-25-DA / S12A | 本次 S12 |
|---|---|---|
| 验证系统 | 1.76.54，boot1/system1 | 1.74.18，boot1/system1 |
| 平台和内核 | 上游记录 Amlogic A113X、Linux 4.9.61 | 系统报告 `amlogic, Gxbb`、Linux 3.14.29 |
| 原生语音进程 | 本次所用的追问注入库针对 ARM32 原生进程 | `mipns-xiaomi` 和 `mico_aivs_lab` 均为 AArch64 ELF；与 S12A 的 ARM32 库不兼容 |
| 根文件系统 | 本次记录中 system1 为只读 SquashFS | 活动 system1 为 UBIFS，根目录可写 |
| 分区布局 | 该机记录：`boot0`/`boot1` 为 mtd2/mtd3，`system0`/`system1` 为 mtd4/mtd5，`data` 为 mtd6 | `boot0`/`boot1` 为 mtd1/mtd2，`system0`/`system1` 为 mtd3/mtd4，`data` 为 mtd5 |
| data 分区 | 该机 `/proc/mtd` 报告 160 MiB；文件系统可用空间小于分区大小 | `/proc/mtd` 报告 24 MiB；`df` 报告文件系统约 14.8 MiB，空间随使用变化 |
| 麦克风 | 上游已验证的链路使用 PDM 和该固件的原生音频接口 | `hw:0,0` 被 `mipns-xiaomi` 占用，ALSA 状态报告 48 kHz、S32_LE、8 通道；不能假定另开一个录音程序就能同时访问 |
| Wi-Fi | 上游硬件页记录 Marvell；该对话中的另一台设备启动记录曾显示 `dhd.ko` 和 BCM 固件文件，尚未核实差异原因 | 设备报告 SDIO vendor/device `0x02d0/0x4345`、`dhd` 驱动；确切芯片及批次仍需核验 |

S12A 上游硬件页写有 128 MiB 闪存，而本次 S12A 的 `/proc/mtd` 数值合计为 250 MiB；两条记录存在矛盾，尚未确认原因。**分区数字相加或 `df` 空间都不能单独证明闪存芯片的物理标称容量。** S12 的零售型号、闪存芯片型号和不同批次的差异同样尚未核实。[上游硬件记录](../../docs/reference/hardware.md) 不能替代对手头设备的检查。

## 功能对照

| 功能 | S12A 1.76.54 本次结果 | S12 1.74.18 本次结果 |
|---|---|---|
| 原生唤醒、DeepSeek 首轮和设备端 TTS | 已做语音验证 | 已做语音验证；音频路径不同，见[本机记录](README.md) |
| 免唤醒追问 | 音箱端原生识别方案已在本机测试；不要求 Mac 常驻 | **实验性混合方案**：音箱取音、Mac 运行 Whisper 转文字；Mac 必须开机、已登录并连同一网络 |
| 未开口退出 | 用户测试约 5 秒等待及静默退出 | 自动语音测试记录约 5 秒未开口后退出；可在本机看板设为 5–10 秒 |
| 追问中重新唤醒小爱 | 已测试交还原生助手 | 在本机候选实现及随后重启的自动测试中观察到物理唤醒交还；原生报时识别及 Speak 事件可见，其他家居技能尚未逐项验证 |
| 首轮本地判停 | 已在该 S12A 的匹配固件部署 | **尚未适配或验收**，不要套用 S12A 的整包 |
| 控制看板 | Mac 提供局域网看板 | 本机有独立的 Mac 看板；不属于当前 PR 的发布内容 |

两台都需要联网：小米原生语音识别、云端模型和在线 TTS 均依赖各自服务。S12 的 Mac 转写是本地 Whisper 推理；转写后的问题仍会按所选配置发给模型服务。实验桥接通过局域网 HTTP 传输短时音频，令牌用于访问控制，但传输未加密；客户端日志可能含对话文字。环境中有人说话时，可能被当作新追问；自动实验也曾出现误触发，不能当成所有家庭环境都稳定。长句、轻声、噪声、断网、Mac 睡眠及长期运行仍需进一步验证。

## S12 混合方案的实测边界

2026-11-15，在上述 S12 上进行了限时实验，并用放慢语速的中文女声自动播放固定问题。过程和结论如下：

1. `native_multirounds` 的两种实验性触发方式均出现首轮回答正常、等待期间没有取得追问文本；这只说明本次实验未成功。
2. 一个为本机 AArch64/glibc 构建的临时探针，在明确的短时测试窗口内拦截原生程序的 `snd_pcm_readi`，没有另开麦克风。**必须按实际调用句柄读取帧大小**：曾错误假定每帧 32 字节，音频有数据却无法正确转写；该测试调用报告每帧 28 字节，按 7 个 32 位样本解析后，Mac 端 Whisper 能识别自动播放的测试句。ALSA 的硬件状态同时报告 8 通道，两个观察不应当被当成对所有 PCM 句柄的通用结论。
3. 本机试验把短时采样、语音活动检测、Mac 本地转写和现有 LLM 会话连起来；自动测试观察到第二轮识别、模型请求及 TTS 播放完成，随后静默退出。捕获窗口约 5 秒等开口，单轮有总时限；停止或完成后清理临时音频。识别结果和日志并不等同于在所有位置、声音和环境下可听见、可用。
4. 当追问窗口检测到新的真实唤醒事件，实验代码停止本轮捕获并交还原生助手；自动报时测试观察到原生识别和 Speak 事件。**这不证明所有命令、竞争时序或正在播报时的打断都已解决。**
5. 实验客户端、64 位探针、配置、Mac 桥接和启动/回滚脚本是该设备的本地定制，**没有作为通用安装器或现成可复现的功能包含在此 PR 中**。Mac 网络地址变化、系统切槽、自动更新、语音服务故障和设备重启都可能影响它；测试中准备并校验了配置备份和模拟中断回退，但不等于验证过 NAND 分区恢复。

本机保护措施包括：匹配硬件、固件和相关程序指纹后才加载探针；限时试运行；启动失败时退回首轮路径；私人配置和备份不公开；正常不采集音频，仅在追问窗口短暂录音并清理。上游维护者如需接入，应先分别审查音频格式、进程间同步、麦克风隐私、唤醒交接、错误处理和可恢复性，再补齐自动化测试及其他设备上的验证，不能通过跳过指纹检查来扩大适用范围。

## 启动与存储提醒

本机曾因启动槽位变化进入另一套 1.74.15 系统：那套系统没有本次的助手启动入口。检查时应分别确认当前根挂载、UBI 与 MTD 对应关系、系统版本和启动变量，**不能仅凭“音箱还能回答”判断启动了哪套系统**。本机恢复到 boot1 后才重新检查 SSH 和助手。

虽然本次 S12 的活动 UBIFS 根目录有空闲空间且显示可写，系统更新或 A/B 切槽可能替换它；这不等于 `/data` 自动扩容，也不说明修改分区安全。不要以清除备份、缩减坏块预留或直接改分区表的方式腾空间。
